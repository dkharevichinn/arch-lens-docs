# B1 — Cyclic modules

| Field | Value |
|---|---|
| Code | `B1` |
| Class | `invariant` → **[block](../gates/block.md)** |
| Analyzer | `GateEvaluator` from `StaticMetrics.Cycles` |
| Commands | `gate` (not listed as a snapshot finding on `map`; cycles still appear in metrics) |

## When it fires

`ModuleGraph` SCCs of size ≥ 2. Each cyclic group that is **not set-equal** to an entry in `baseline.knownCycles` becomes one B1 finding.

Message: `cyclic modules: A, B` (module ids sorted Ordinal).

Fingerprint: `ForTypeEdge("B1", "A,B", "", [])` — joined sorted ids, empty kinds.

`knownFindings` does **not** silence B1. Only `knownCycles`.

Two-module “chatty pair” is this rule. There is no P2 code.

## Example

```mermaid
flowchart LR
  Account --> Gameplay
  Gameplay --> Account
```

Account.Contracts referencing Home.Contracts while Home implementation references Account implementation can close a **module** cycle even if each edge looks locally justified.

## How to fix

1. Break one direction: both features should depend **inward** on contracts / shared, not on each other's bodies.
2. Extract the shared concept to `shared`.
3. Invert a callback with an event/port owned by one module.

## What not to do

- Do **not** add the cycle to `knownCycles` unless it is frozen legacy. That is a permanent exemption.
- Do **not** hide a cycle by merging two modules in YAML while leaving two assemblies that still depend both ways — you only renamed the node.
- Do **not** expect `map`'s Findings tab to list B1; look at Metrics → Cycles and at `gate-report.json`.

See also [cycles](../metrics/cycles.md), [B5](B5.md), [R1](R1.md), [G1](G1.md).
