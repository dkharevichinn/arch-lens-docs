# G1 — New inter-module edge (classified)

| Field | Value |
|---|---|
| Code | `G1` |
| Class | **`invariant` → block** for violating or cycle-forming edges; **`trigger`** for new to-contract / to-shared |
| Analyzer | `SnapshotDiffer` |
| Commands | `gate --against` only |

## When it fires

Each **new** scored inter-module **type pair** (present in current, absent in previous):

| Situation | Class | Message |
|---|---|---|
| Pair is an [A1](A1.md)/[A2](A2.md) violation, and neither the A* fingerprint nor the G1 fingerprint is in `knownFindings` | invariant | `new violating edge {from} -> {to}` |
| Pair closes a module SCC that was not together in previous and not covered by `knownCycles` | invariant | `new cycle-forming edge {from} -> {to}` |
| Target role is `contract` | trigger | `new edge {from} -> {to} to-contract` |
| Target role is `shared` | trigger | `new edge {from} -> {to} to-shared` |
| Otherwise | (no G1) | — |

Fingerprint: `ForTypeEdge("G1", fromTypeId, toTypeId, kinds)`.

Existing pairs are not reclassified. Visual `diff` does not emit G1.

## Example

Adding `Gameplay.Score → Account.Cache` (implementation) between snapshots → violating G1 **and** A1 (A1 may already be known; G1 still blocks unless its own fingerprint is known). Adding `Gameplay.Score → Account.Contracts.IAuth` → trigger to-contract.

## How to fix

Violations: same as A1/A2. Cycle-forming: same as [B1](B1.md). To-contract/to-shared: review whether the new legal edge is the API you meant to grow ([A4](A4.md)/[B9](B9.md)).

## What not to do

- Do **not** put only the A1 fingerprint in `knownFindings` and assume G1 is gone — G1 has a **different** fingerprint.
- Do **not** add `knownCycles` to hide a **new** cycle-forming edge without fixing it.
- Do **not** skip `--against` in the factory pipeline.

See also [A1](A1.md), [B1](B1.md), [G3](G3.md).
