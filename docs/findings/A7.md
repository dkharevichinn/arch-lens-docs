# A7 — `InternalsVisibleTo` открывает внутренности сборке, не являющейся тестовой

| Поле | Значение |
|---|---|
| Код | `A7` |
| Класс | `invariant` → вердикт **[block](../gates/block.md)**, код выхода 5 |
| Кто выдаёт | `InternalsVisibleToAnalyzer.Analyze`: проход по списку `ModuleCatalog.Friends`, который заполняет `RoslynGraphExtractor.ExtractFriends` из атрибутов `[assembly: InternalsVisibleTo(...)]` |
| Команды | `map` — находка снимка (`findings.json`, вкладка Findings); `gate` — проходит в `gate-report.json`, если отпечатка нет в `knownFindings` |
| Отпечаток | `ForTypeEdge("A7", assemblyName, friendName, [])` — SHA-256 от `A7\n{сборка-владелец}\n{сборка-друг}\n`; виды рёбер пусты |
| Сообщение | `InternalsVisibleTo {assembly} -> {friend}`; для снимков Swift с механизмом `testableImport` — `@testable import {assembly} -> {friend}`; для неизвестного механизма подставляется его имя как есть |

## Термины

**Дружественная сборка** (`FriendAssembly`) — запись с тремя полями: `Assembly` (сборка, открывающая свои `internal`-члены), `Friend` (сборка, которой они открыты) и `Mechanism` (`internalsVisibleTo` по умолчанию; `testableImport` для Swift). Для .NET записи получаются из атрибутов уровня сборки `System.Runtime.CompilerServices.InternalsVisibleToAttribute` с одним строковым аргументом; MSBuild-элемент `<InternalsVisibleTo Include="X" />` в `.csproj` генерирует тот же атрибут. Из строки берётся часть до первой запятой без пробелов, поэтому суффикс `, PublicKey=…` на сопоставление не влияет (тест `Public_key_suffix_is_ignored_when_matching_catalog`). Дубликаты удаляются, список сортируется по ordinal.

**Каталог модулей** (`ModuleCatalog`) — перечень сборок снимка с их ролями и модулями; в него попадают только сборки, у которых есть хотя бы один тип в решении ([сборка, модуль и роль](../glossary.md#module)). Друг, которого в каталоге нет, для A7 невидим.

**Тестовая сборка** — сборка с ролью `test`: по конвенции суффиксы `.Tests`, `.UnitTests`, `.IntegrationTests`, либо `role: test` в `arch-lens.yaml`. Роль решает всё: сборка `AccountTests` без точки перед суффиксом по конвенции получит роль `implementation`, и дружба с ней станет нарушением, пока роль не объявлена в YAML (тест `Testable_import_test_role_friend_is_allowed` показывает разрешённый случай с явной ролью).

**Почему тесты — исключение.** Роль `test` вынесена из проверки границ во всём семействе A: тесты обязаны видеть тело проверяемого модуля, и открыть им `internal`-типы — единственный способ тестировать реализацию, не делая её публичной (что увеличило бы [A3](A3.md)). Любая другая сборка, получившая доступ к внутренностям, приобретает скрытый API в обход контракта, поэтому такая дружба — инвариант, а не предмет ревью.

## Когда срабатывает

```text
для каждой записи friend из ModuleCatalog.Friends:
    friend.Friend отсутствует в каталоге сборок    → пропуск
    роль сборки friend.Friend == test              → пропуск
    иначе                                          → A7 (invariant)
```

Находка получает `FromModule` — модуль сборки-владельца (или `null`, если её нет в каталоге), `ToModule` — модуль сборки-друга, пустые свидетельства. Анализатор не проверяет, пользуется ли друг открытыми внутренностями на самом деле: нарушением считается само объявление, потому что оно создаёт возможность обхода, которую граф типов не увидит.

Друг с ролью `host` — нарушение (тест `Host_friend_is_A7`): корень композиции должен собирать модули через публичные контракты и методы регистрации, а не через `internal`-классы. Дружба между сборками **одного модуля** — тоже нарушение (`Product_friend_is_A7`: `Account → Account.Infrastructure`), потому что роли `implementation` и `infrastructure` внутри модуля общаются через публичные типы, а не через `internal`. Друг, отсутствующий в решении, — например `DynamicProxyGenAssembly2`, которого требуют библиотеки моков, — пропускается (`Friend_not_in_catalog_is_skipped`).

Отпечаток зависит только от пары имён сборок, поэтому находка стабильна между запусками и исчезает ровно тогда, когда атрибут удалён или роль друга стала `test`. Гейт пропускает A7 из снимка: если отпечатка нет в `knownFindings`, вердикт `block` (тест `Unknown_A7_fingerprint_blocks_the_gate`). При чтении снимка из `graph.json` записи берутся из массива `internalsVisibleTo`, так что A7 работает и на сохранённых снимках.

## Пример

Тест `Product_friend_is_A7`: сборка `Account` (роль `implementation`) объявляет друга `Account.Infrastructure` (роль `infrastructure`, тот же модуль `Account`). Находка: `From = Account`, `To = Account`, сообщение `InternalsVisibleTo Account -> Account.Infrastructure`, отпечаток `ForTypeEdge("A7", "Account", "Account.Infrastructure", [])`, свидетельств нет.

```csharp
// Сборка Account: AssemblyInfo.cs
[assembly: InternalsVisibleTo("Account.Infrastructure")]              // A7: роль infrastructure, даже внутри модуля
[assembly: InternalsVisibleTo("App.Host")]                            // A7: роль host
[assembly: InternalsVisibleTo("Account.Tests, PublicKey=0024000004…")] // разрешено: роль test, PublicKey отбрасывается
[assembly: InternalsVisibleTo("DynamicProxyGenAssembly2")]            // пропускается: такой сборки нет в снимке
```

```xml
<!-- Account.csproj: эквивалент атрибута -->
<ItemGroup>
  <InternalsVisibleTo Include="Account.Tests" />   <!-- разрешено, потому что Account.Tests имеет роль test -->
</ItemGroup>
```

Сам продукт использует разрешённый вариант: проекты `ArchLens.Analysis`, `ArchLens.Reporting` и другие объявляют `<InternalsVisibleTo Include="ArchLens.Tests" />`, а `ArchLens.Tests` по конвенции имеет роль `test`.

## Где смотреть в отчёте

- **Вкладка Findings отчёта `map`** — строка `A7 | invariant | Account | Account | InternalsVisibleTo Account -> Account.Infrastructure |` с пустой колонкой Evidence: у правила нет рёбер между типами.
- **`findings.json`** — те же поля и `fingerprint`.
- **`graph.json`, массив `internalsVisibleTo`** — все извлечённые записи с полями `assembly` и `friend` (поле `mechanism` записывается только для механизмов, отличных от `internalsVisibleTo`), включая разрешённые дружбы с тестами и пропущенных друзей вне решения; это полный список, а находки — его отфильтрованная часть.
- **`gate-report.json`** — объект `"rule": "A7"`, `"class": "invariant"`, если отпечатка нет в `knownFindings`; в консоли `verdict=block`.
- **Вкладки Matrix и Metrics** дружбу не показывают: она не является ребром графа и не влияет ни на одну метрику.

## Как исправить

1. Удалите атрибут или MSBuild-элемент для каждой сборки-друга, чья роль не `test`.
2. Если друг из **другого модуля** пользовался `internal`-типами, опубликуйте нужную форму через `X.Contracts` (порт или DTO) или, для общих примитивов, через `shared`; рост поверхности отметит [A4](A4.md), и это нормальный путь.
3. Если друг из **того же модуля** (`Account.Infrastructure` использует внутренности `Account`), сделайте зависимость явной: объявите в `Account` публичный интерфейс, который реализует инфраструктура, — это одно осознанное увеличение [A3](A3.md); либо объедините две сборки в одну, если граница между ними не нужна.
4. Если друг — тестовый проект с нестандартным именем, не принимайте находку, а объявите роль: `modules.assemblies: - assembly: AccountTests` с `role: test` в `arch-lens.yaml`.
5. Если друг — `host`, перенесите точку входа модуля в публичный метод регистрации (`AddAccount(this IServiceCollection)`), который хост вызывает без доступа к `internal`.
6. Запустите `arch-lens map` и убедитесь, что строка исчезла.

**Когда допустимо принять.** Осознанные исключения редки: например, проект бенчмарков или инструментов разработчика в том же решении, который нельзя назвать тестами и которому действительно нужны внутренности. В унаследованном коде первый `arch-lens baseline` заносит существующие отпечатки в `knownFindings`; отдельную дружбу принимают, вписав отпечаток из `findings.json` и объяснив причину в коммите. Поскольку отпечаток зависит только от имён сборок, принятая находка не всплывёт до тех пор, пока дружба не будет удалена, — поэтому у каждой такой записи должен быть владелец и план.

## Чего не делать

- Не открывайте внутренности соседней реализации, чтобы обойти [A1](A1.md): вместо явного нарушения границы вы получаете скрытый API без контракта и без следа в графе типов.
- Не открывайте внутренности хосту: корень композиции собирает модули через контракты и публичные методы регистрации.
- Не исключайте сборку-друга из решения ради тишины: связь остаётся в коде, а анализатор просто перестаёт её видеть.
- Не присваивайте продуктовой сборке роль `test` в YAML: помимо A7 она выпадет из графа модулей, всех метрик и остальных правил.
- Не полагайтесь на `PublicKey` как на защиту: анализатор его отбрасывает, и по смыслу подписанная дружба остаётся дружбой.
