# C4 — Dominant type growth

| Field | Value |
|---|---|
| Code | `C4` |
| Class | `trigger` |
| Analyzer | `SnapshotDiffer` |
| Commands | `gate --against` only |

## When it fires

For each scored module, `deltaTypes = current.types - previous.types` (missing previous counts as 0). Let `S` be the sum of **positive** deltas. A module fires if:

- `delta ≥ 5`, and
- `delta / S ≥ 0.7`

If `S == 0` (no growth anywhere), C4 does not fire.

Fingerprint: `ForTypeEdge("C4", moduleId, "", [])`. Message: `dominant type growth: {module}`.

## Example

Previous: Account 40 types, Home 40. Current: Account 80, Home 41. Account delta 40, S = 41, 40/41 ≥ 0.7 and 40 ≥ 5 → C4 on Account.

## How to fix

Spread genuine feature work across the modules that own it, or split the growing blob ([C1](C1.md)) **before** it absorbs the iteration. If the growth is an intentional rewrite of one module, treat the trigger as a review checklist, not a mute.

## What not to do

- Do **not** add dummy types to other modules to dilute `S`. That is fraud and pollutes [C1](C1.md)/[F2](F2.md).
- Do **not** omit `--against` so C4 never exists. Pair it with G1–G3/A8 in CI.

See also [C1](C1.md), [G3](G3.md), [moduleSize](../metrics/moduleSize.md).
