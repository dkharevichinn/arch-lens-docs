# B5 — Core SCC size

| Field | Value |
|---|---|
| Code | `B5` |
| Class | `trigger` |
| Analyzer | `StaticMetricsCalculator` / `CorePathAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |
| Threshold | `gate.coreSizeMin` (default **3**) |

## When it fires

Largest **cyclic** SCC has size ≥ `coreSizeMin`. 2-cycles are already [B1](B1.md); B5 means the **core grew**.

Message: `core SCC: A, B, C` (Ordinal ids). Fingerprint: `ForTypeEdge("B5", "A,B,C", "", [])`.

`coreSize` / `coreShare` are always written to metrics even when B5 does not fire.

## Example

YAML `coreSizeMin: 3`. A↔B is B1 only. A↔B↔C with all three cyclic fires B5.

## How to fix

Peel modules out of the strongly connected core until the remaining cycle is a known 2-cycle or gone. Extract shared kernels instead of a mesh of feature modules.

## What not to do

- Do **not** raise `coreSizeMin` to 99 to “disable” B5. That hides a growing hairball.
- Do **not** silence B5 while leaving B1 knownCycles for the same set — you still have a core.

See also [coreSize](../metrics/coreSize.md), [coreShare](../metrics/coreShare.md), [B1](B1.md).
