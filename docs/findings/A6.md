# A6 — Сигнатура контракта использует тип чужого модуля вне `shared`

| Поле | Значение |
|---|---|
| Код | `A6` |
| Класс | `trigger` → вердикт **[triggers](../gates/triggers.md)**, код выхода 4, если нет ни одной находки классов `invariant` и `ratchet` |
| Кто выдаёт | `ContractQualityAnalyzer.AddForeignSignatures`: рёбра сигнатурных видов из контрактной сборки в тип другого модуля с ролью, отличной от `shared` |
| Команды | `map` — находка снимка (`findings.json`, вкладка Findings); `gate` — проходит в `gate-report.json`, если отпечатка нет в `knownFindings` |
| Отпечаток | `ForTypeEdge("A6", fromTypeId, toTypeId, kinds)` — SHA-256 от `A6\n{тип-источник}\n{тип-цель}\n{сигнатурные виды через запятую}` |
| Сообщение | `contract signature uses foreign type {fromTypeId} -> {toTypeId}` |

## Термины

**Сигнатурные виды рёбер** (`SignatureKinds` в коде) — пять из девяти [видов рёбер](../glossary.md#edge-kinds), которые описывают форму типа, а не его поведение: `parameter` (тип параметра метода, конструктора или индексатора), `return` (возвращаемый тип), `fieldType` (тип поля **или свойства** — экстрактор записывает тип свойства этим же видом), `genericArgument` (аргумент обобщённого типа: `Task<Session>` даёт ребро на `Session`, сам `Task` как внешний тип отбрасывается) и `attribute` (класс атрибута на типе, методе или свойстве). Не входят: `call`, `inheritance`, `implementation`, `binding`.

**Чужой модуль** — модуль с другим идентификатором, чем у контрактной сборки-источника ([сборка, модуль и роль](../glossary.md#module)). Ссылка контракта на тип собственного модуля A6 не интересует, даже если это реализация (тем случаем занимается [A2](A2.md)).

**`shared`** — роль общего ядра: примитивы, идентификаторы, деньги, время. Тип из `shared` в сигнатуре контракта — норма, ради которой роль и существует, поэтому такие рёбра исключены из A6.

**Учитываемый модуль** — модуль без ролей `host` и `test` ([словарь](../glossary.md#scored)). Цель ребра должна быть учитываемой: параметр типа из сборки `host` или `test` в контракте A6 не даёт (это чистое нарушение [A2](A2.md)).

## Когда срабатывает

Анализатор проходит по рёбрам снимка и отбирает те, для которых одновременно выполняются условия:

```text
edge.Kind ∈ { parameter, return, fieldType, genericArgument, attribute }
оба типа найдены, обе сборки есть в каталоге
роль сборки-источника == contract
роль сборки-цели      != shared
модуль источника      != модуль цели
модуль цели учитываемый (роль не host и не test)
```

Отобранные рёбра группируются по паре `(тип-источник, тип-цель)`, веса суммируются по видам; на пару создаётся одна находка класса `trigger` с `FromModule`, `ToModule`, сообщением и одним свидетельством вида `from → to (parameter:2,return:1)`. Отпечаток включает отсортированный набор видов: появление нового вида между теми же типами даёт новый отпечаток и возвращает принятую находку (тест `Aggregates_signature_kinds_on_one_A6_pair`).

Роль цели, кроме `shared`, для A6 безразлична, и это отличает правило от семейства A1/A2:

| Цель в другом модуле | A6 | Что ещё |
|---|---|---|
| `contract` | `trigger` | [A2](A2.md) молчит: контракт → контракт разрешён таблицей ролей |
| `implementation`, `infrastructure`, `ui` | `trigger` | [A2](A2.md) даёт `invariant` на ту же пару типов — две строки с разными отпечатками |
| `shared` | нет | ничего |
| `host`, `test` | нет | только [A2](A2.md) |

Вызов чужого контракта из тела метода в контракте — не A6, а [A5](A5.md) (`Contract_call_to_foreign_non_shared_is_not_A6`). Наследование интерфейса от чужого интерфейса или базового класса (`inheritance`, `implementation`) A6 не отмечает (`Inheritance_and_implementation_are_not_A6`).

Гейт пропускает A6 из снимка, отбрасывая отпечатки из `knownFindings`; синтеза нет.

## Пример

Тест `Contract_parameter_to_foreign_impl_is_A6`: `Gameplay.Contracts::G.IScore` (роль `contract`, модуль `Gameplay`) имеет параметр типа `Account::A.Cache` (роль `implementation`, модуль `Account`) — находка `From = Gameplay`, `To = Account`, свидетельство `(parameter:1)`, отпечаток `ForTypeEdge("A6", "Gameplay.Contracts::G.IScore", "Account::A.Cache", ["parameter"])`; рядом на ту же пару встанет A2.

Тест `Contract_parameter_to_foreign_contract_is_A6`: `Home.Contracts::H.INav` с параметром `Account.Contracts::A.IAuth` — только A6, `From = Home`, `To = Account`. Тесты `Contract_parameter_to_shared_is_not_A6` (`SharedKernel::S.Email`) и `Contract_parameter_to_same_module_is_not_A6` (`Account::A.Auth` из своего модуля) находок не дают.

```csharp
// Сборка Home.Contracts, роль contract, модуль Home
public interface INav
{
    void Open(Account.Contracts.IAuth auth);      // parameter → A6 (Home.Contracts::H.INav -> Account.Contracts::A.IAuth)
    Account.Contracts.IAuth Current { get; }      // fieldType: тип свойства → тот же отпечаток дополняется видом
    Task<Account.Contracts.Session> Login();      // genericArgument на Session → отдельная пара типов, отдельная находка
    void Send(SharedKernel.Email to);             // shared → не A6
    void Show(Home.Contracts.Page page);          // свой модуль → не A6
}
```

Здесь `INav → IAuth` даст одну находку со свидетельством `(fieldType:1,parameter:1)`, а `INav → Session` — вторую, со свидетельством `(genericArgument:1)`.

## Где смотреть в отчёте

- **Вкладка Findings отчёта `map`** — строка `A6 | trigger | Home | Account | contract signature uses foreign type Home.Contracts::H.INav -> Account.Contracts::A.IAuth | Home.Contracts::H.INav → Account.Contracts::A.IAuth (fieldType:1,parameter:1)`. Если цель — не контракт, рядом стоит строка [A2](A2.md) класса `invariant` с той же парой типов.
- **`findings.json`** — те же поля и `fingerprint`.
- **`gate-report.json`** — объект `"rule": "A6"`, `"class": "trigger"`, если отпечатка нет в `knownFindings`; в консоли `verdict=triggers`.
- **Вкладка Metrics, таблица Modules** — такие рёбра увеличивают `Fan-out` модуля-источника и `Fan-in` цели; если контракты двух модулей ссылаются друг на друга, раздел Cycles покажет цикл, и сработает [B1](B1.md).

## Как исправить

1. По свидетельству определите чужой тип и вид связи: параметр, возвращаемое значение, свойство, аргумент обобщения или атрибут.
2. Объявите собственный DTO или интерфейс в контракте потребителя (`Home.Contracts`), а преобразование из чужого типа выполняйте в реализации `Home`, где зависимость от `Account.Contracts` законна. Контракт тогда говорит на языке своего модуля.
3. Если тип — действительно общий примитив (идентификатор пользователя, деньги, адрес), перенесите его в сборку `shared`; после этого ребро выходит из области A6 у всех потребителей. Помните, что `shared` не должна зависеть ни от одного модуля ([A1](A1.md)).
4. Проверьте направление: возможно, не `Home` должен знать типы `Account`, а `Account` — реагировать на события `Home`. Инверсия убирает ребро вместо его переупаковки.
5. Типы инфраструктуры и UI в сигнатурах контракта устраняйте в первую очередь: там A6 сопровождается блокирующей [A2](A2.md).

**Когда допустимо принять.** Связь «контракт → чужой контракт» иногда является осознанным решением: контракт навигации оболочки принимает идентификаторы из контракта учётных записей, событие одного модуля несёт DTO другого. Если команда согласна с этой связью, добавьте отпечаток из `findings.json` в `knownFindings` (или зафиксируйте текущее состояние командой `arch-lens baseline`) и опишите решение в коммите. Отпечаток содержит набор видов, поэтому расширение связи — например, чужой тип появился ещё и в возвращаемом значении — вернёт находку, и это повод перепроверить решение.

## Чего не делать

- Не переносите чужой тип реализации в его контракт, чтобы погасить [A2](A2.md), оставляя A6: вы всё равно опубликовали форму чужого модуля в своём API.
- Не объявляйте сборку-цель `shared` в YAML ради тишины: `shared` — ядро без зависимостей, а не склад «всего, на что ссылаются несколько модулей».
- Не заменяйте тип на `object`, `string` с JSON или `Dictionary<string, object>`: связь остаётся, но исчезает из отчёта и из поля зрения ревьюеров.
- Не объединяйте два модуля под одним идентификатором в YAML только для того, чтобы ребро стало внутримодульным.
- Не заносите A6 в `knownFindings` рефлекторно: это список осознанных решений, а не способ пройти гейт.
