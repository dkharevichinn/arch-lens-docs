# E4 — Duplicate concept names

| Field | Value |
|---|---|
| Code | `E4` |
| Class | `trigger` |
| Analyzer | `DuplicateConceptAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Public types in **different scored modules**. Short name = last segment of the type id, arity `` `1 `` stripped.

Match if:

- names equal **OrdinalIgnoreCase**, or
- both names length **≥ 8** and Levenshtein distance on **uppercased** names **≤ 2**

Cap 20 pairs, order distance asc then ids Ordinal. Fingerprint: `ForTypeEdge("E4", typeIdA, typeIdB, [])` with A < B Ordinal.

Message: `duplicate concept: {A} ~ {B}`.

Same module is ignored. Non-public types are ignored.

## Example

`Account.Foo` and `Home.Foo` → distance 0. `Account.Processor` and `Home.Processer` (length ≥ 8, distance 1) → E4. `Account.User` vs `Home.Users` may not fire if length < 8 and not equal ignore-case.

## How to fix

Rename for the bounded context (`AccountUser` vs `HomeUser`) **or** extract one shared type if it is truly the same concept. Prefer shared only when both modules should own the same definition ([B9](B9.md)).

## What not to do

- Do **not** rename to `Foo1`/`FooX` to beat Levenshtein.
- Do **not** hide types as `internal` solely to leave the catalog; if they are a public concept, they should be named distinctly.

See also [D3](D3.md), [A6](A6.md).
