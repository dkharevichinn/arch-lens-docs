# B3 — Feedback weight ratchet

| Field | Value |
|---|---|
| Code | `B3` |
| Class | `ratchet` → **[block](../gates/block.md)** |
| Analyzer | `GateEvaluator` vs `baseline.ratchets.feedbackWeight` |
| Commands | `gate` |

## When it fires

Modules are ordered with the **Eades–Lin–Smyth** greedy layering (deterministic Ordinal ties). Inter-module edges that point **against** that order contribute their weight to `feedbackWeight`. Fires when current **>** baseline.

Fingerprint: `ForTypeEdge("B3", "", "", [])`.

These are DSM “above the diagonal” edges once rows follow dependency layers.

## Example

Layer order `SharedKernel → Account → Home`. A new `SharedKernel → Home` is forward. A new `Home → Account` after Account already depends on Home is feedback if the heuristic placed Account after Home.

## How to fix

1. Point dependencies **down** the layering: features → contracts/shared, UI → contracts, never shared → features.
2. Replace a back edge with a port owned by the lower layer.

## What not to do

- Do **not** reorder assemblies in YAML hoping the heuristic will flip; order is computed from the graph, not from the YAML list.
- Do **not** split an edge into many tiny edges with the same direction — weight still sums.
