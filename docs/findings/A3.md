# A3 — Число публичных типов в теле модуля выросло (`publicInImplementation`)

| Поле | Значение |
|---|---|
| Код | `A3` |
| Класс | `ratchet` → вердикт **[block](../gates/block.md)**, код выхода 5, когда значение для модуля строго больше порога в `baseline.json`; `trigger` → вердикт **[triggers](../gates/triggers.md)**, код выхода 4, когда ключа модуля в `baseline.json` ещё нет |
| Кто выдаёт | `GateEvaluator.AddDictionaryFindings("A3", …)`: сравнение словаря `StaticMetrics.PublicInImplementation` со словарём `baseline.ratchets.publicInImplementation` |
| Команды | только `arch-lens gate --baseline`; команда `map` эту находку **не** создаёт, и на вкладке Findings она не появляется никогда |
| Метрика | [`publicInImplementation`](../metrics/publicInImplementation.md) — колонка **Public impl** таблицы Modules на вкладке Metrics |
| Отпечаток | `ForTypeEdge("A3", moduleId, "", [])` — один на модуль, одинаковый для `ratchet` и `trigger`; `FromModule`, `ToModule` и `Evidence` пусты |
| Сообщение | `publicInImplementation[{module}] {cur} > baseline {bas}` для `ratchet`; `new module/contract, review surface: {module}` для `trigger` |

## Термины

**Роль сборки** и **модуль** определены в словаре ([сборка, модуль и роль](../glossary.md#module)). Для A3 важно, что модуль объединяет несколько сборок с разными ролями: у модуля `Account` тело — это сборки `Account` (`implementation`) и `Account.Infrastructure` (`infrastructure`), граница — `Account.Contracts` (`contract`).

**Учитываемый модуль** — модуль, у которого есть хотя бы один тип в сборке с ролью, отличной от `host` и `test` ([словарь](../glossary.md#scored)). Типы `host` и `test` в подсчёт не входят: корень композиции и тесты — потребители всех модулей, а не часть их архитектуры.

**Публичный тип** — тип с эффективной доступностью `public`: вложенный `public`-класс внутри `internal`-класса считается `internal` и в A3 не входит ([идентификатор типа](../glossary.md#type-id)). Вид типа не важен: класс, запись, интерфейс, структура, перечисление и делегат учитываются одинаково.

**Порог `ratchet`** — число в `baseline.json`, которое запрещено ухудшать ([словарь](../glossary.md#ratchet)). У A3 таких порогов столько, сколько учитываемых модулей: по одному целому на идентификатор модуля в словаре `ratchets.publicInImplementation`.

## Когда срабатывает

Подсчёт выполняет `StaticMetricsCalculator.Calculate` при каждом запуске `map`, `baseline` и `gate`:

```text
для каждого учитываемого модуля M графа модулей:
    publicInImplementation[M] = 0                      ← ключ создаётся даже при нуле
для каждого типа T снимка:
    сборка T не в каталоге или роль host | test        → пропуск
    T.Accessibility == "public"
      и роль сборки T ∈ { implementation, infrastructure }
                                                       → publicInImplementation[модуль T] += 1
```

Типы сборок с ролями `contract`, `ui` и `shared` счётчик не увеличивают, даже если они публичные: контракт публичен по назначению (его измеряет [A4](A4.md)), `shared` — тоже, а роль `ui` из подсчёта исключена кодом. Ключ словаря — **идентификатор модуля**, поэтому публичные типы `Account` и `Account.Infrastructure` складываются в одно число `publicInImplementation["Account"]`, а перенос публичного типа между этими двумя сборками ничего не меняет.

Гейт сравнивает словари так:

```text
для каждого ключа M текущего словаря:
    M отсутствует в baseline.ratchets.publicInImplementation
        → trigger  «new module/contract, review surface: M»
    иначе current[M] > baseline[M]
        → ratchet  «publicInImplementation[M] {current} > baseline {baseline}»
ключи, оставшиеся только в baseline (модуль удалён или переименован), находок не дают
```

Сравнение строгое: равенство — тишина, уменьшение — тишина без автоматического переписывания порога. Поскольку ключ создаётся для каждого учитываемого модуля, новый модуль вызывает `trigger`, даже если все его типы `internal`, даже если он состоит из одной контрактной сборки или имеет роль `shared`: гейт просит просмотреть поверхность нового модуля, а следующий `arch-lens baseline` фиксирует ключ. Переименование модуля выглядит для гейта так же, как появление нового.

Находка синтезируется **после** фильтрации по `knownFindings`, поэтому её отпечаток в этом списке не проверяется. Единственные способы убрать `ratchet` A3 — вернуть число публичных типов к порогу или осознанно поднять порог командой `arch-lens baseline`. Текст `new module/contract` общий для A3 и A4: код правила в отчёте показывает, о каком словаре речь.

## Пример

Тест `A3_counts_public_implementation_and_infrastructure_only`: пять модулей по одному типу. `Impl::I.Public` (роль `implementation`, `public`) и `Infra::F.Public` (`infrastructure`, `public`) дают по единице; `Ui::U.Public` и `Con::C.Public` публичны, но их роли не учитываются; `Hidden::H.Internal` — реализация, но тип `internal`. Итог: `Con 0, Hidden 0, Impl 1, Infra 1, Ui 0` — все пять ключей присутствуют, отсортированы по ordinal.

```csharp
// Сборка Account, роль implementation, модуль Account
public sealed class AccountService { }    // +1 к publicInImplementation["Account"]
internal sealed class TokenCache { }      // не считается
// Сборка Account.Infrastructure, роль infrastructure, тот же модуль Account
public sealed class AccountDbContext { }  // +1 к publicInImplementation["Account"], итого 2
// Сборка Account.Contracts, роль contract
public interface IAuth { }                // здесь не считается: это contractSurface (A4)
```

Гейт (тест `A3_public_count_above_baseline_is_block`): в `baseline.json` записано `"publicInImplementation": { "Account": 3 }`, текущее значение 4 — находка класса `ratchet` с сообщением `publicInImplementation[Account] 4 > baseline 3`, отпечаток `ForTypeEdge("A3", "Account", "", [])`, вердикт `block`. При текущем значении 2 и пороге 3 гейт молчит, и порог остаётся равным 3 (`A3_public_count_below_baseline_is_pass_without_auto_tighten`). Модуль `NewMod`, которого в baseline нет, даёт `trigger` с сообщением `new module/contract, review surface: NewMod` и вердикт `triggers` (`New_A3_key_is_triggers_not_block`).

## Где смотреть в отчёте

- **Вкладка Findings отчёта `map` строку A3 не покажет никогда.** Отсутствие A3 в таблице ничего не говорит о числе публичных типов.
- **Вкладка Metrics, таблица Modules, колонка `Public impl`** — текущее значение словаря для каждого модуля; строки таблицы — учитываемые модули, те же ключи, что в словаре.
- **`metrics.json`, ключ `publicInImplementation`** — объект «идентификатор модуля → целое»; это источник сравнения для гейта.
- **`baseline.json`, ключ `ratchets.publicInImplementation`** — действующие пороги по модулям.
- **`gate-report.json`** — объект с `"rule": "A3"`, классом `ratchet` или `trigger`, пустыми `fromModule`, `toModule` и `evidence`; в консоли `verdict=block` или `verdict=triggers`.
- **`graph.json`, массив `types`** — у каждого типа записаны `assembly` и `accessibility`; сравнение двух файлов показывает, какие именно типы модуля стали публичными.

## Как исправить

1. Прочитайте сообщение: оно называет модуль, текущее значение и порог. В таблице Modules найдите строку модуля и сверьте колонку `Public impl`.
2. Найдите новые публичные типы: сравните `graph.json` текущего и предыдущего запуска по типам с `"accessibility": "public"` в сборках `implementation` и `infrastructure` этого модуля.
3. Сделайте новые типы реализации `internal`. Поведение наружу должно выходить через интерфейсы в `X.Contracts`; регистрация в контейнере работает и с `internal`-типами, если метод регистрации (`AddAccount(this IServiceCollection)`) объявлен в самой сборке реализации — это один публичный тип на модуль, а не по одному на сервис.
4. Если тип должен быть виден только тестам, оставьте его `internal` и откройте тестовой сборке через `[InternalsVisibleTo]`: для сборок с ролью `test` правило [A7](A7.md) это разрешает.
5. Запустите `arch-lens gate`: значение должно стать не больше порога.

**Когда допустимо принять.** Публичный тип в реализации оправдан, когда он — точка входа модуля, которую нельзя выразить контрактом: метод регистрации, `partial`-класс для генератора кода, тип, который требует публичности сериализатор или фреймворк. В этом случае выполните `arch-lens baseline` и закоммитьте `baseline.json` вместе с изменением, объяснив в описании коммита, почему порог поднят. Для нового модуля `trigger` — предмет ревью, а не ошибка: после просмотра поверхности тот же `arch-lens baseline` фиксирует ключ. Запись в `knownFindings` на A3 не влияет.

## Чего не делать

- Не переписывайте `baseline.json` при каждом PR «потому что один класс»: так порог перестаёт быть порогом.
- Не переносите тип в сборку `ui` или `contract`, чтобы вывести его из подсчёта, если он не является ни UI, ни контрактом: в контракте он увеличит [A4](A4.md) и, скорее всего, вызовет [A5](A5.md), а в UI исказит картину архитектуры.
- Не считайте `trigger` нового модуля разрешением навсегда: после следующего `baseline` его значение станет порогом `ratchet`.
- Не заносите отпечаток A3 в `knownFindings`: гейт его не читает, находка вернётся на следующем запуске.
- Не переименовывайте модуль ради сброса счётчика: новый ключ даст `trigger`, старый останется в baseline, а ревьюер увидит оба.
