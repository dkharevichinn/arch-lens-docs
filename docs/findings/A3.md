# A3 — Public types in implementation

| Field | Value |
|---|---|
| Code | `A3` |
| Class | **`ratchet` → block** when the count for a module is strictly greater than baseline; **`trigger`** when the module key is new |
| Analyzer | `GateEvaluator` (from `publicInImplementation`) |
| Commands | `gate` only (not a snapshot finding on `map`) |

## When it fires

`StaticMetricsCalculator` counts, per **scored module**, public types in assemblies whose role is `implementation` or `infrastructure`. **UI, host, test, contract, shared** do not increment this map.

- Current `[module] > baseline.ratchets.publicInImplementation[module]` → ratchet, message `publicInImplementation[{module}] {cur} > baseline {bas}`.
- Module missing from the baseline map → trigger `new module/contract, review surface: {module}`.

Fingerprint: `ForTypeEdge("A3", moduleId, "", [])`.

UI stays out because XAML/MAUI often needs `public` types; [A1](A1.md) still stops UI from depending on foreign implementations.

## Example

```csharp
// Account/AccountService.cs  (implementation)
public sealed class AccountService { } // each new public type increments A3 for module Account
internal sealed class AccountService { } // does not
```

A new `Billing` module with three public implementation types and no baseline key yields a **trigger**, not a block. The next `arch-lens baseline` records `publicInImplementation.Billing = 3`.

## How to fix

1. Default new implementation types to **`internal`**. Expose behavior through `X.Contracts`.
2. If a type must be public for DI or serializers in-process, prefer registering it against a **contract port** and keeping the class `internal` with `[InternVisibleTo]` **only to tests** (see [A7](A7.md)).
3. After a genuine new public DI entry point, **re-run `baseline`** so the ratchet moves up on purpose.

## What not to do

- Do **not** widen `public` “for convenience” and then rewrite baseline every PR. That deletes the ratchet.
- Do **not** move types into a `ui` assembly just to drop them from A3 if they are not UI.
- Do **not** treat a **new module trigger** as a pass forever — it is a review item; the next baseline makes it a ratchet.

See also [publicInImplementation](../metrics/publicInImplementation.md), [A4](A4.md).
