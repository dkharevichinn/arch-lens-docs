# B6 — Longest condensation path

| Field | Value |
|---|---|
| Code | `B6` |
| Class | `trigger` |
| Analyzer | `StaticMetricsCalculator` / `CorePathAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |
| Threshold | `gate.maxModulePath` (default **6**) |

## When it fires

Collapse each SCC (including singletons) to a DAG node. `maxModulePath` is the number of **edges** on the longest path in that DAG (deterministic DP, Ordinal representative ids).

Fires when `maxModulePath >= maxModulePath` threshold. One finding per repo: fingerprint `ForTypeEdge("B6", "", "", [])`.

Message: `maxModulePath {value} >= {threshold}`.

## Example

`Host` is not in `ModuleGraph`. A chain `UI → App → Billing → Payments → Ledger → Posting → Audit` is 6 edges if those are scored modules — fires at the default.

## How to fix

Shorten the chain: introduce a contract at a mid layer, or merge steps that are not real modules. Avoid stacked “manager” modules that only forward calls.

## What not to do

- Do **not** set `maxModulePath: 100` in YAML to green CI.
- Do **not** hide length by stuffing many assemblies into one module id if they are independently deployed/owned — you only lie to the DSM.
