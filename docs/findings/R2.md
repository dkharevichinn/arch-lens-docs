# R2 — Unbound port

| Field | Value |
|---|---|
| Code | `R2` |
| Class | `trigger` |
| Analyzer | `RuntimeAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

A **port** is an interface or abstract **class** (abstract records are not ports). Constructor injections of that port on types that are **container consumers** (appear as service or implementation on a **non-test** registration) are counted.

If that port has **no non-test registration** (`ByService` empty of product registrars), R2 fires.

Opaque `Add*` wrappers **count as bound** (implementation unknown, but not unbound). Test-only registrations do not bind a production port.

Message: `port {typeName} injected in {n} types, no DI registration`. Fingerprint: `ForTypeEdge("R2", portId, "", [])`.

`metrics.runtime.unboundPorts` is the count of these findings.

## Example

```csharp
public sealed class GameSetupViewModel
{
    public GameSetupViewModel(IGameRepository repo) { } // IGameRepository is a port
}
services.AddTransient<GameSetupViewModel>(); // VM registered, port not → R2
```

Fix:

```csharp
services.AddTransient<IGameRepository, EfGameRepository>();
```

## How to fix

Register the port in the composition root (host). If the port is optional/plugin, register an explicit null-object. If extraction cannot see a third-party `AddRefitClient`, an **opaque** wrapper is enough to mark it bound.

## What not to do

- Do **not** register the port only in test `Startup` — production R2 remains.
- Do **not** replace the interface with the concrete type in the constructor just to drop the port count; that often creates [A1](A1.md).
- Do **not** silence R2 for a port that is injected in production code. That is a runtime failure.

See also [R1](R1.md), [runtime](../metrics/runtime.md), [E3](E3.md).
