# A8 — Из публичного типа контракта исчез публичный член по сравнению с предыдущим снимком

| Поле | Значение |
|---|---|
| Код | `A8` |
| Класс | `trigger` → вердикт **[triggers](../gates/triggers.md)**, код выхода 4, если нет ни одной находки классов `invariant` и `ratchet` |
| Кто выдаёт | `SnapshotDiffer.AddA8`: сравнение списков `PublicApi` публичных типов контрактных сборок предыдущего снимка с текущим; вызывается из `GateEvaluator.Evaluate` только при наличии обоих снимков |
| Команды | только `arch-lens gate --baseline baseline.json --against old-graph.json`; без `--against` правило не может сработать; `map` находку не создаёт, `diff --from … --to …` показывает изменения контрактов, но находок и вердикта не выносит |
| Отпечаток | `ForTypeEdge("A8", typeId, memberDocId, [])` — SHA-256 от `A8\n{идентификатор типа}\n{идентификатор члена}\n`; по одному на удалённый член |
| Сообщение | `removed public API {memberDocId} from {typeId}` |

## Термины

**Предыдущий снимок** — файл `graph.json`, который записала команда `map` в прошлый раз (в CI обычно с основной ветки) и путь к которому передан в `--against`. Гейт читает его через `GraphSnapshotReader`: принимается только формат `version: 2`; типы восстанавливаются вместе с полями `accessibility`, `publicMembers` и `publicApi`, а роли сборок — из массива `modules` файла, поверх которых применяются явные записи `modules.assemblies` из текущего `--config`. Роль `contract` для A8 определяется именно по **предыдущему** снимку.

**`PublicApi` типа** — отсортированный список идентификаторов документации всех явно объявленных членов типа с объявленной доступностью `public`, кроме аксессоров свойств и событий и членов из сгенерированных файлов ([словарь](../glossary.md#public), подробный разбор — на странице [A4](A4.md)). Список хранится в `graph.json` только у типов, у которых он непуст.

**Идентификатор документации** (`ISymbol.GetDocumentationCommentId`) — строка того же формата, что в XML-документации: префикс вида члена (`M:` метод или конструктор, `P:` свойство, `F:` поле, `E:` событие, `T:` вложенный тип), полное имя содержащего типа с пространством имён, имя члена, для обобщённых типов и методов — число параметров типа после обратного апострофа (одного у типов, двух у методов), для методов и индексаторов — типы параметров в скобках с полными именами (`System.String`, `System.Collections.Generic.IReadOnlyList{System.Int32}`, `@` для `ref` и `out`). Например, метод `void Login(string user)` интерфейса `Account.Contracts.IAuth` имеет идентификатор `M:Account.Contracts.IAuth.Login(System.String)`, конструктор — `M:Account.Contracts.LoginRequest.#ctor(System.String)`.

Что в идентификатор **не входит**: имена параметров, возвращаемый тип (кроме операторов преобразования), модификаторы, значения по умолчанию, аннотации допустимости `null`, атрибуты. Отсюда главное следствие для A8: **идентификатор — это и есть API**. Переименование метода, изменение типа параметра, добавление или удаление параметра, перенос типа в другое пространство имён или сборку меняют идентификатор, и старый идентификатор считается удалённым. Переименование параметра и смена возвращаемого типа идентификатор не меняют, и A8 их не замечает, хотя для потребителей с именованными аргументами и для бинарной совместимости это ломающие изменения.

## Когда срабатывает

```text
для каждого типа T предыдущего снимка:
    T.Accessibility == "public" и роль сборки T (по каталогу предыдущего снимка) == contract
    remaining = PublicApi типа с тем же Id в текущем снимке; пусто, если типа нет
    для каждого id ∈ T.PublicApi, которого нет в remaining:
        A8 (trigger): FromModule = модуль T, ToModule = null, Evidence = []
```

Из алгоритма следуют свойства правила.

- Одна находка на каждый исчезнувший идентификатор: удаление типа целиком даёт столько находок, сколько у него было публичных членов (тест `Deleted_public_contract_type_is_A8_per_previous_member`).
- Тип сравнивается по [идентификатору](../glossary.md#type-id) `Сборка::Пространство.Имя`: переименование типа, перенос в другую сборку или пространство имён выглядят как удаление всех его членов.
- Добавление членов — не A8 (`Added_contract_member_is_not_A8`); за рост поверхности отвечает [A4](A4.md), за новый тип с единственным потребителем — [G2](G2.md).
- Тип, публичный в реализации, а не в контракте, не отслеживается (`Non_contract_public_type_deletion_is_not_A8`); члены `internal`-типов контракта тоже.
- Тип, который стал `internal`, но сохранил публичные члены, A8 не отмечает: список `PublicApi` собирается по объявленной доступности членов и не зависит от доступности типа, поэтому `remaining` совпадает с прошлым списком. Такое изменение уменьшит `contractSurface`, но останется для гейта незамеченным.
- Член, ставший `internal` или `private`, исчезает из `PublicApi` и даёт A8.

Находка синтезируется после фильтрации по `knownFindings` и с этим списком не сверяется. Порога в `baseline.json` у A8 нет: правило относительное и сравнивает два снимка. Как только в `--against` начинает передаваться новый `graph.json`, в котором члена уже нет, находка исчезает сама.

## Пример

Тест `Removed_contract_member_is_A8`: в предыдущем снимке публичный тип `Account.Contracts::A.IAuth` контрактной сборки `Account.Contracts` имел `PublicApi = ["M:A.IAuth.Login", "M:A.IAuth.Logout"]`, в текущем — только `["M:A.IAuth.Login"]`. Единственная находка: класс `trigger`, отпечаток `ForTypeEdge("A8", "Account.Contracts::A.IAuth", "M:A.IAuth.Logout", [])`, сообщение `removed public API M:A.IAuth.Logout from Account.Contracts::A.IAuth`, свидетельств нет.

```csharp
// Было (old-graph.json): сборка Account.Contracts, пространство имён Account.Contracts
public interface IAuth
{
    void Login(string user);       // M:Account.Contracts.IAuth.Login(System.String)
    void Logout();                 // M:Account.Contracts.IAuth.Logout
    string Realm { get; }          // P:Account.Contracts.IAuth.Realm
}

// Стало (текущее решение)
public interface IAuth
{
    void Login(string userName);   // тот же идентификатор: переименование параметра A8 не видит
    void Login(Guid userId);       // новый идентификатор M:…Login(System.Guid): добавление — не A8, это A4
    string Realm { get; }
}
// A8: removed public API M:Account.Contracts.IAuth.Logout from Account.Contracts::Account.Contracts.IAuth
```

Если бы вместо удаления `Logout` тип параметра `Login` сменили со `string` на `Guid`, находка была бы про `M:Account.Contracts.IAuth.Login(System.String)`: старый идентификатор исчез, новый добавился.

## Где смотреть в отчёте

- **Вкладка Findings отчёта `map` строку A8 не покажет никогда**, и в `findings.json` её нет: правило требует второго снимка, которого у `map` нет.
- **`gate-report.json`** — объект с `"rule": "A8"`, `"class": "trigger"`, `"fromModule": "Account"`, `"toModule": null`, пустым `evidence` и сообщением с идентификатором члена; в консоли `verdict=triggers`, `findings=N`, если ничто другое не блокирует.
- **`graph.json`, массив `types`** — поле `publicApi` каждого публичного типа контракта; сравнение двух файлов вручную даёт тот же список, что и A8.
- **Отчёт команды `arch-lens diff --from … --to …`** открывается на вкладке Contracts и показывает удалённые и добавленные члены наглядно, но это визуализация: вердикта и кодов выхода `4`/`5` у `diff` нет.

## Как исправить

1. Относитесь к каждой строке A8 как к ломающему изменению: по идентификатору члена найдите потребителей (вкладка Findings и `typeEdges` в `graph.json` показывают, кто ссылается на тип) и убедитесь, что все они обновлены в том же изменении.
2. Предпочитайте аддитивную эволюцию: добавьте новый член, пометьте старый `[Obsolete]`, переведите потребителей, а удаление выполните отдельным изменением, когда `--against` уже указывает на снимок с обоими членами. Тогда единственным разговором на гейте будет [A4](A4.md).
3. Если удаление намеренное и потребители обновлены, находка остаётся `trigger`: гейт вернёт код выхода `4`, и решение о прохождении принимает политика CI, а не `baseline.json`.
4. Следите за тем, чтобы `--against` указывал на актуальный `graph.json` основной ветки: сравнение с устаревшим снимком даёт A8 на давно согласованные удаления.

**Когда допустимо принять.** A8 принимается не файлом, а решением: удаление или переименование публичного члена контракта — осознанный разрыв совместимости, который должен быть описан в коммите и списке изменений, а потребители внутри решения — обновлены. Механизма заглушить A8 через `knownFindings` или `baseline.json` нет и не нужно: после следующего снимка основной ветки находка исчезает сама.

## Чего не делать

- Не убирайте `--against` из конвейера, чтобы не видеть A8: вместе с ним пропадут [G1](G1.md), [G2](G2.md), [G3](G3.md) и [C4](C4.md), а `diff` гейт не заменяет.
- Не считайте изменение типа параметра «совместимым уточнением»: идентификатор меняется, и для потребителей это новый метод.
- Не считайте переименование параметра или смену возвращаемого типа безопасными потому, что A8 молчит: правило видит только идентификаторы, а именованные аргументы и бинарная совместимость ломаются.
- Не делайте тип контракта `internal` ради «сокращения поверхности»: потребители сломаются, A8 этого не заметит, и разрыв пройдёт мимо гейта.
- Не переносите тип в сборку реализации, чтобы «убрать» его из контракта: A8 отметит каждый его член, а у потребителей появится [A1](A1.md).
- Не вписывайте отпечатки A8 в `knownFindings`: гейт их не читает.
