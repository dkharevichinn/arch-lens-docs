# A8 — Removed public contract API

| Field | Value |
|---|---|
| Code | `A8` |
| Class | `trigger` |
| Analyzer | `SnapshotDiffer` |
| Commands | `gate --against old-graph.json` only. `diff --from/--to` visualizes contracts but **does not** emit A8. |

## When it fires

For every **public type** that lived in a **contract** assembly in the **previous** snapshot, each documentation id in `PublicApi` that is missing on the same type id in current (or the type disappeared entirely — every previous id is “removed”).

Adding members is not A8. That is [A4](A4.md) (ratchet) and possibly [G2](G2.md).

Message: `removed public API {memberDocId} from {typeId}`.

Fingerprint: `ForTypeEdge("A8", typeId, memberDocId, [])`.

Requires `--against`. Without it, A8 cannot fire.

## Example

Previous `Account.Contracts.IAuth` public API included `M:Account.Contracts.IAuth.Login(System.String)`. Current interface:

```csharp
public interface IAuth
{
    void SignIn(string user); // Login removed → A8 on the Login doc id
}
```

Deleting `IAuth` entirely emits A8 for **each** previous public member id of that type.

## How to fix

1. Treat contract removals as **breaking changes**: keep the old member, add a new one, or version the assembly.
2. If the rename is intentional, ship it as an explicit break: accept the A8 trigger (or update consumers first, then remove in a follow-up with a new `--against` snapshot).
3. Prefer additive evolution so A4 is the only conversation.

## What not to do

- Do **not** skip `--against` in CI to hide A8. Visual `diff` is not the gate.
- Do **not** change `GetDocumentationCommentId()` surface by renaming parameters as a “compatible” change — the id is the API.
- Do **not** move a type to the implementation assembly to make A8 “go away”; you broke every consumer and likely added [A1](A1.md).

See also [A4](A4.md), [G2](G2.md), [contractSurface](../metrics/contractSurface.md).
