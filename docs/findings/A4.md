# A4 — Публичная поверхность контрактной сборки выросла (`contractSurface`)

| Поле | Значение |
|---|---|
| Код | `A4` |
| Класс | `ratchet` → вердикт **[block](../gates/block.md)**, код выхода 5, когда поверхность сборки строго больше порога в `baseline.json`; `trigger` → вердикт **[triggers](../gates/triggers.md)**, код выхода 4, когда ключа сборки в `baseline.json` ещё нет |
| Кто выдаёт | `GateEvaluator.AddDictionaryFindings("A4", …)`: сравнение словаря `StaticMetrics.ContractSurface` со словарём `baseline.ratchets.contractSurface` |
| Команды | только `arch-lens gate --baseline`; команда `map` эту находку **не** создаёт, и на вкладке Findings она не появляется никогда |
| Метрика | [`contractSurface`](../metrics/contractSurface.md) — таблица **Contracts** (`Unit`, `Surface`) на вкладке Metrics |
| Отпечаток | `ForTypeEdge("A4", assemblyName, "", [])` — один на контрактную сборку, одинаковый для `ratchet` и `trigger`; `FromModule`, `ToModule` и `Evidence` пусты |
| Сообщение | `contractSurface[{assembly}] {cur} > baseline {bas}` для `ratchet`; `new module/contract, review surface: {assembly}` для `trigger` |

## Термины

**Контрактная сборка** — сборка с ролью `contract` ([сборка, модуль и роль](../glossary.md#module)). Именно её публичные типы и члены составляют API модуля для остальных модулей.

**Публичный тип** — тип с эффективной доступностью `public` ([идентификатор типа](../glossary.md#type-id)); вложенный `public` внутри `internal` не публичен.

**`PublicApi` и `PublicMembers`.** Для каждого типа экстрактор `RoslynGraphExtractor.CollectPublicApi` собирает отсортированный список идентификаторов документации (`ISymbol.GetDocumentationCommentId`) его членов, у которых одновременно: объявленная доступность `public`; член объявлен явно (не синтезирован компилятором — конструктор по умолчанию, члены записей вроде `Equals` и `Deconstruct`, поле `value__` перечисления не входят); член не объявлен исключительно в сгенерированных файлах (`*.g.cs`, `*.g.i.cs`, `*.generated.cs`); член не является аксессором свойства или события (`get`, `set`, `add`, `remove`). В список попадают методы и конструкторы (`M:`), свойства (`P:`), поля, в том числе значения перечислений (`F:`), события (`E:`), операторы и вложенные типы (`T:`). Члены интерфейса публичны по умолчанию, поэтому все они учитываются. `PublicMembers` — длина этого списка. Список собирается независимо от доступности самого типа, но в поверхность он входит только у публичных типов (см. [словарь](../glossary.md#public)).

**Ключ словаря — имя сборки, а не идентификатор модуля.** В отличие от [A3](A3.md), где публичные типы `Account` и `Account.Infrastructure` суммируются под ключом модуля `Account`, поверхность считается отдельно для каждой контрактной сборки: ключ — `Account.Contracts`. Если YAML привязал к одному модулю две контрактные сборки, у каждой будет своя строка в таблице Contracts и свой порог. Следствие: переименование контрактной сборки создаёт новый ключ (и `trigger`), а переименование модуля при неизменном имени сборки на A4 не влияет.

## Когда срабатывает

Подсчёт в `StaticMetricsCalculator.Calculate`:

```text
для каждого типа T, чья сборка имеет роль contract:
    contractSurface[T.Assembly] существует (создаётся при первом типе сборки со значением 0)
    T.Accessibility == "public"  →  contractSurface[T.Assembly] += 1 + T.PublicMembers
```

Контрактная сборка без единого типа ключа не получает; сборка только из `internal`-типов получает ключ со значением `0`. Вложенный публичный тип учитывается дважды: как член контейнера (идентификатор `T:` в `PublicApi` контейнера) и как самостоятельный тип со своими членами.

Гейт сравнивает словари так же, как для A3:

```text
для каждого ключа S текущего словаря:
    S отсутствует в baseline.ratchets.contractSurface → trigger «new module/contract, review surface: S»
    иначе current[S] > baseline[S]                    → ratchet «contractSurface[S] {current} > baseline {baseline}»
ключи, оставшиеся только в baseline, находок не дают
```

Сравнение строгое и без допуска. Удаление членов и типов поверхность уменьшает и A4 не вызывает; исчезновение публичного API отслеживает [A8](A8.md) при `gate --against`. Добавление и удаление в одном изменении могут компенсировать друг друга: минус один член и плюс один член дают то же число, и A4 молчит. Находка синтезируется после фильтрации по `knownFindings`, поэтому в этот список её заносить бесполезно.

## Пример

Тест `A4_surface_is_public_types_plus_their_public_members`: в сборке `Account.Contracts` публичный интерфейс `Account.Contracts::A.IAuth` с тремя публичными членами и `internal`-тип `A.Hidden` с 99 публичными членами. Поверхность равна `1 + 3 = 4`; тип `Hidden` не добавляет ничего, сколько бы членов у него ни было.

```csharp
// Сборка Account.Contracts, роль contract
public interface IAuth                    // +1 за публичный тип
{
    Task<Session> Login(string user);     // M:Account.Contracts.IAuth.Login(System.String)  +1
    void Logout();                        // M:Account.Contracts.IAuth.Logout                +1
    string Realm { get; }                 // P:Account.Contracts.IAuth.Realm                 +1; аксессор get не считается
}
internal sealed class Hidden              // тип не публичный: 0, сколько бы публичных членов у него ни было
{
    public void A() { }
}
// contractSurface["Account.Contracts"] = 4
```

Если в `IAuth` добавить `void LoginWithSso(string id);`, поверхность станет `5`, и при пороге `4` гейт выдаст `contractSurface[Account.Contracts] 5 > baseline 4` с вердиктом `block`. Публичное перечисление `public enum Tier { Free, Pro }` добавило бы `1 + 2 = 3`: значения перечисления — явно объявленные публичные поля.

Новая сборка `New.Contracts` с поверхностью `2`, которой нет в baseline, даёт единственную находку класса `trigger` и вердикт `triggers` (тест `Verdict_is_triggers_when_only_new_key_trigger_exists`).

## Где смотреть в отчёте

- **Вкладка Findings отчёта `map` строку A4 не покажет никогда.**
- **Вкладка Metrics, таблица Contracts** — колонка `Unit` содержит имя контрактной сборки, колонка `Surface` — текущее значение; строки — ключи словаря.
- **`metrics.json`, ключ `contractSurface`** — объект «имя сборки → целое»; источник сравнения для гейта.
- **`baseline.json`, ключ `ratchets.contractSurface`** — действующие пороги по сборкам.
- **`gate-report.json`** — объект с `"rule": "A4"`, классом `ratchet` или `trigger`, пустыми `fromModule`, `toModule` и `evidence`.
- **`graph.json`, массив `types`** — у каждого типа записаны `publicMembers` и, если список непуст, `publicApi`; сравнение двух файлов показывает, какие именно члены добавились.
- **Чип `contracts` в шапке отчёта** считает модули с контрактной сборкой, а не поверхность; команда `arch-lens diff --from … --to …` показывает изменения контрактов наглядно, но находок и вердикта не выносит.

## Как исправить

1. Прочитайте сообщение: имя сборки, текущее значение и порог. Найдите добавленные члены, сравнив `publicApi` типов этой сборки в двух `graph.json` или открыв отчёт `arch-lens diff`.
2. Для каждого нового типа и члена ответьте на вопрос, нужен ли он **другому модулю**. Если потребитель только внутри модуля, верните тип в сборку реализации и сделайте его `internal`.
3. Предпочитайте узкие порты и DTO без форм хранения: сущность EF или ответ внешнего API в контракте — это не поверхность, а утечка, которую отметят [A5](A5.md) и [A6](A6.md).
4. Если поверхность выросла намеренно — версионированный API, новый порт для соседнего модуля, — выполните `arch-lens baseline` и закоммитьте `baseline.json` вместе с функциональностью.
5. Запустите `arch-lens gate` и убедитесь, что значение не превышает порог.

**Когда допустимо принять.** Контракт и должен расти, когда модулю появляется новый потребитель или новая операция для соседа; `ratchet` существует не для запрета роста, а для того, чтобы каждый шаг проходил ревью. Принятие оформляется только командой `arch-lens baseline` с объяснением в описании коммита; для новой контрактной сборки `trigger` снимается той же командой после просмотра её состава. При `gate --against` дополнительно проверьте [G2](G2.md): новый публичный тип с единственным потребителем — признак того, что порт сделан под одного клиента.

## Чего не делать

- Не переносите типы реализации в `*.Contracts`, чтобы удовлетворить [A1](A1.md): поверхность раздувается, а [A5](A5.md) и [A6](A6.md) отмечают конкретные классы и чужие типы.
- Не открывайте членов «на вырост»: каждый публичный член контракта — обязательство перед потребителями, и его удаление позже станет [A8](A8.md).
- Не сбрасывайте baseline «ради одного метода»: это и есть работа порога.
- Не обходите порог через `internal` плюс `[InternalsVisibleTo]` в сторону потребителя: это [A7](A7.md), и такой API остаётся невидимым для каталога.
- Не заносите отпечаток A4 в `knownFindings`: гейт его не читает.
