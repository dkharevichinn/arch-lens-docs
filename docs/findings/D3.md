# D3 — Cluster pulls toward another module

| Field | Value |
|---|---|
| Code | `D3` |
| Class | `trigger` |
| Analyzer | `CommunityAnalyzer` (label propagation) |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Undirected graph of **all scored types** (not per-module). Label propagation: init label = typeId; each iteration types in Ordinal order take the majority neighbor label (ties: Ordinal-min label); stop at stability or 50 iterations.

Clusters (same label) of size **≥ 4**: majority module (ties: Ordinal-min name). Each type whose module ≠ majority is a finding `cluster pulls toward {majority}`.

Cap **20** findings (typeId then majority, Ordinal). Fingerprint: `ForTypeEdge("D3", typeId, majorityModule, [])`.

## Example

A `Pricing` helper type lives in `Catalog` but has edges only into a four-type `Billing` clique. Label propagation assigns it Billing's community → D3 with `ToModule = Billing`.

## How to fix

Move the type to the majority module, or cut the foreign edges and depend on that module's **contract** instead of its types.

## What not to do

- Do **not** rename types to shuffle Ordinal tie-breaks.
- Do **not** treat cap 20 as “only 20 problems exist”. Fix the worst misplaced types; re-run.
