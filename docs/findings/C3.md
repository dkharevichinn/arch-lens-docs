# C3 — UI LOC outweighs implementation

| Field | Value |
|---|---|
| Code | `C3` |
| Class | `trigger` |
| Analyzer | `SizeBalanceAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Inside one scored module, `uiLoc > implementationLoc` **and** `implementationLoc > 0`. Infrastructure LOC is **not** in this comparison.

Fingerprint: `ForTypeEdge("C3", moduleId, "", [])`. Message: `ui outweighs implementation: {module}`.

A UI-only module with 0 implementation LOC does **not** fire (the `implementationLoc > 0` guard).

## Example

`Home.UI` has 4k LOC of views; `Home` implementation has 800 LOC of use-cases → C3. Thick views calling other modules' implementations will also show [A1](A1.md).

## How to fix

Move orchestration, mapping, and policy out of UI types into the implementation assembly (or a dedicated application layer still role `implementation`). Keep views as adapters.

## What not to do

- Do **not** move view-models into implementation **and** keep them referenced as UI-only if they still are views — fix roles honestly.
- Do **not** zero out implementation LOC by deleting the body; you want a thicker application layer, not an empty one.

See also [layerLoc](../metrics/layerLoc.md), [A1](A1.md).
