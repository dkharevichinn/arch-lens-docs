# P3 — Isolated (dead) module

| Field | Value |
|---|---|
| Code | `P3` |
| Class | `trigger` |
| Analyzer | `SizeBalanceAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Scored module with `fanIn == 0`, `fanOut == 0`, and `types > 0`. **Shared is not exempt** — an isolated kernel is still a signal.

Fingerprint: `ForTypeEdge("P3", moduleId, "", [])`. Message: `dead module: {module}`.

Host/test are not scored. A module that only the host references still has fan-in 0 on `ModuleGraph` (host edges are omitted) — it can look isolated even if the composition root uses it. Wire a **product** consumer or accept that host-only modules look dead at this grain.

## Example

`Iso` assembly with types but no edges to/from other scored modules → P3. `SharedKernel` used by nobody yet → P3.

## How to fix

Connect it for real (another feature depends on its contract) or delete/merge it. If only the host should see it, that is expected composition — document and optionally `knownFindings` **after** review.

## What not to do

- Do **not** add a spurious reference from a random module to clear P3.
- Do **not** confuse P3 with [E2](E2.md) (type-level) or [F2](F2.md) (no tests).

See also [fanInOut](../metrics/fanInOut.md), [E2](E2.md).
