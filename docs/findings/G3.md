# G3 — Blast radius

| Field | Value |
|---|---|
| Code | `G3` |
| Class | `trigger` |
| Analyzer | `SnapshotDiffer` |
| Commands | `gate --against` only |
| Threshold | `gate.blastRadiusThreshold` (default **4**) |

## When it fires

Count scored modules whose **type id set** or **outgoing module set** changed vs previous (union of module ids). If that count **>** `blastRadiusThreshold`, one finding for the repo.

Fingerprint: `ForTypeEdge("G3", "", "", [])`. Message: `blast radius {n} exceeds threshold {threshold}`.

This is a **snapshot diff**, not `git log` (despite older catalog notes). [G4](G4.md) is the git co-change rule.

## Example

Default threshold 4. Touching types or outgoing edges in 5 modules in one `--against` pair → G3. A focused change in two modules does not.

## How to fix

Split the change into smaller architectural steps, or justify a cross-cutting refactor and raise the threshold **explicitly** in YAML for that repo if 4 is routinely too tight — after calibration, not as a first response.

## What not to do

- Do **not** set `blastRadiusThreshold` to 10_000.
- Do **not** confuse G3 with coverage of files; it is module-level type/edge churn.

See also [C4](C4.md), [G1](G1.md), [G4](G4.md).
