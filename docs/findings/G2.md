# G2 — Контрактная сборка получила новый публичный тип с единственным внешним потребителем

| Поле | Значение |
|---|---|
| Код | `G2` |
| Класс | `trigger` → вердикт **[triggers](../gates/triggers.md)**, код выхода 4, если в отчёте гейта нет находок классов `invariant` и `ratchet` |
| Кто выдаёт | `SnapshotDiffer.AddG2`; `GateEvaluator.Evaluate` вызывает `SnapshotDiffer.Diff` только когда есть и текущий, и предыдущий снимок |
| Команды | только `arch-lens gate --baseline baseline.json --against old-graph.json`; без `--against` не выдаётся никогда; команды `map` и `diff` её не создают, на вкладке Findings она не появляется |
| Отпечаток | `ForTypeEdge("G2", assemblyName, "", [])` — имя контрактной сборки, пустая цель, пустой список видов; одна находка на сборку |
| Сообщение | `contract {assembly} gained a single-consumer public type` |
| Поля | `FromModule` и `ToModule` пусты, `Evidence` пуст; тип в находке не называется |

## Термины

Базовые понятия — [сборка, модуль и роль](../glossary.md#module), [публичность](../glossary.md#public), [учитываемый модуль](../glossary.md#scored), [идентификатор типа](../glossary.md#type-id) — определены в словаре. Для G2 нужны ещё три.

**Контрактная сборка** — сборка с ролью `contract`: по конвенции это `*.Contracts`, либо роль задана в `arch-lens.yaml`. Её публичные типы — опубликованная граница модуля, за совместимость которой модуль отвечает перед остальными.

**Новый публичный тип** — идентификатор типа с `accessibility == "public"` в этой сборке, которого не было среди публичных типов той же сборки в снимке из `--against`. Новым считается и переименованный тип, и тип, который был `internal` и стал `public`: в предыдущем множестве публичных идентификаторов его не было.

**Внешний потребитель** — учитываемый модуль, отличный от модуля контрактной сборки, у которого хотя бы один тип имеет ребро любого вида в новый тип. Считаются различные модули, а не типы и не рёбра. Собственная реализация модуля (`Account` для `Account.Contracts`) потребителем не считается, потому что модуль один и тот же; типы сборок `host` и `test` не считаются, потому что не учитываются.

## Когда срабатывает

```text
для каждой сборки S с ролью contract, принадлежащей модулю M:
  previousPublic = публичные типы S в снимке из --against
  для каждого публичного типа T сборки S в текущем снимке, T ∉ previousPublic:
    consumers = { модуль(F) : есть ребро F → T, F — учитываемый тип, модуль(F) ≠ M }
    если |consumers| == 1 → одна находка G2 для сборки S, проверка остальных типов S прекращается
```

Ноль внешних потребителей находки не даёт: тип опубликован, но пока никем не используется — за рост поверхности отвечает [A4](A4.md). Два и больше потребителей находки не дают тоже: это настоящий общий API. Ровно один потребитель — признак того, что частная договорённость двух модулей оформлена как публичный контракт, за совместимость которого владелец теперь отвечает перед одним-единственным клиентом, а каждое удаление члена будет отмечено [A8](A8.md).

Находка синтезируется гейтом после фильтрации по `knownFindings`, поэтому этот список на неё не влияет. Она исчезает сама, когда тип появляется в снимке, переданном через `--against`, — то есть после слияния изменения и обновления эталонного `graph.json`. Типы, которые существовали в предыдущем снимке и лишь теперь получили единственного потребителя, правило не рассматривает.

Одна находка на сборку означает, что три новых типа с одним потребителем каждый дадут одну строку G2, и по отчёту гейта не понять, какой именно тип её вызвал: это нужно выяснить по снимкам (см. ниже).

## Пример

Юнит-тест `New_public_contract_type_with_one_foreign_consumer_is_G2`: в предыдущем снимке в `Account.Contracts` есть публичный `A.IAuth`; в текущем добавился публичный `Account.Contracts::A.LoginRequest`, на который ссылается `Gameplay::G.Score`. Множество внешних потребителей — `{Gameplay}`, его размер `1`: находка `contract Account.Contracts gained a single-consumer public type` с отпечатком `ForTypeEdge("G2", "Account.Contracts", "", [])`, пустыми `fromModule`, `toModule` и `evidence`.

```csharp
// Account.Contracts/SsoTicket.cs — новый публичный тип контрактной сборки модуля Account
public sealed record SsoTicket(string Token, DateTimeOffset ExpiresAt);

// Home/SsoLoginHandler.cs — единственный внешний потребитель (модуль Home)
internal sealed class SsoLoginHandler
{
    public void Handle(SsoTicket ticket) { /* … */ }   // parameter: Home → Account.Contracts
}
// → G2 «contract Account.Contracts gained a single-consumer public type»
// Если SsoTicket начнёт использовать и Gameplay, потребителей станет два, и G2 замолчит;
// рост поверхности Account.Contracts при этом всё равно отметит A4.
```

## Где смотреть в отчёте

- **`gate-report.json`** — единственное место: объект с `"rule": "G2"`, `"class": "trigger"`, пустыми `fromModule`, `toModule`, `evidence` и сообщением с именем сборки. В консоли — `verdict=triggers`, если ничего не блокирует.
- **Какой тип стал причиной**, по отчёту гейта не видно. Запустите `arch-lens diff --from old-graph.json --to new-graph.json`: отчёт откроется на вкладке Contracts, где перечислены добавленные публичные типы и члены по контрактным сборкам. Либо сравните записи `types` двух файлов `graph.json` для этой сборки, отбирая `"accessibility": "public"`.
- **Кто потребитель** — записи `edges` текущего `graph.json` с `"to"` равным идентификатору нового типа; сгруппируйте источники по модулям, отбросив `host`, `test` и собственный модуль контракта.
- **Вкладка Metrics, таблица Contracts** (`Unit | Surface`) — поверхность сборки выросла; в том же отчёте гейта, скорее всего, есть [A4](A4.md) с сообщением `contractSurface[{assembly}] {cur} > baseline {bas}`.

## Как исправить

1. Найдите тип по `diff` или по `graph.json` и определите, чьё это понятие.
2. Если тип существует только ради запроса одного потребителя (объект-параметр, ответ под конкретный экран), подумайте, не должен ли он принадлежать потребителю или быть выражен через уже существующие типы контракта и примитивы.
3. Если это общий примитив (идентификатор, интервал, деньги), перенесите его в `shared`; тогда он перестанет быть публичным типом контракта.
4. Если тип попал в контракт из реализации случайно (например, стал `public` ради тестов), верните ему `internal` или перенесите в сборку реализации.
5. Если это настоящий API, которым по плану воспользуются другие модули, оставьте как есть: находка требует ревью, а не правки, и исчезнет после обновления эталонного снимка.

**Когда допустимо принять.** Публикация типа до появления второго потребителя — нормальная практика, если она осознанна. Заносить что-либо в `baseline.json` не нужно и бесполезно: G2 не читает `knownFindings`. Достаточно зафиксировать решение в описании изменения; после слияния `graph.json` основной ветки станет новым `--against`, тип перестанет быть новым, и G2 замолчит. Если поверхность контракта выросла, отдельно примите [A4](A4.md) командой `arch-lens baseline`.

## Чего не делать

- Не добавляйте фиктивную ссылку из третьего модуля, чтобы потребителей стало два: это лишнее межмодульное ребро, которое увидит [G1](G1.md), и ложное основание для публичного API.
- Не делайте тип `internal`, если потребителю он нужен: потребитель скопирует его себе, и вы получите [E4](E4.md) вместо G2.
- Не расширяйте тип новыми членами «чтобы оправдать публикацию» — рост поверхности отслеживает [A4](A4.md).
- Не ищите способ заглушить G2 через `knownFindings`: гейт синтезирует её после фильтрации.
