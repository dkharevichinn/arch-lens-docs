# G2 — Contract gained a single-consumer public type

| Field | Value |
|---|---|
| Code | `G2` |
| Class | `trigger` |
| Analyzer | `SnapshotDiffer` |
| Commands | `gate --against` only |

## When it fires

Per **contract assembly**: if **any** public type id exists in current but not previous, and that type has **exactly one** external scored module consuming it, the assembly gets one G2 finding.

Fingerprint: `ForTypeEdge("G2", assemblyName, "", [])`. Message: `contract {assembly} gained a single-consumer public type`.

One finding per assembly, not per type. Types that already existed are ignored even if they become single-consumer.

## Example

You add `Account.Contracts.SsoTicket` used only from `Home` → G2. If both Home and Gameplay reference it, G2 does not fire (might still [A4](A4.md)).

## How to fix

If the type is a private collaboration between two modules, consider moving it to shared **or** inlining a DTO in the consumer contract ([A6](A6.md) trade-off). If it is a real API, add the second consumer or accept the trigger as “published too early”.

## What not to do

- Do **not** add a fake reference from a third module.
- Do **not** make the type `internal` in Contracts if others need it — fix ownership instead.

See also [A4](A4.md), [A8](A8.md), [G1](G1.md).
