# C1 — Module size outlier

| Field | Value |
|---|---|
| Code | `C1` |
| Class | `trigger` |
| Analyzer | `SizeBalanceAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Both must hold for a scored module:

- `types ≥ 20`
- `types ≥ 3 × medianTypes` (median of type counts across scored modules)

Fingerprint: `ForTypeEdge("C1", moduleId, "", [])`. Message: `size outlier: {module}`.

LOC is shown in metrics but **not** in the C1 predicate.

## Example

Modules with type counts 4, 5, 6, 60. Median 5.5 (even N). `60 ≥ 20` and `60 ≥ 16.5` → C1 on the blob.

A module with 18 types never fires C1 even if it is 10× the median.

## How to fix

Split along **feature** boundaries (new modules with their own contracts), not along technical layers inside the same blob. Extract a true shared kernel only for types many modules already need.

## What not to do

- Do **not** split into `Foo.Core`, `Foo.Domain`, `Foo.App` that still cycle ([B1](B1.md)) or envy one cell ([P1](P1.md)).
- Do **not** delete types or empty them to get under 20 without moving responsibilities.

See also [moduleSize](../metrics/moduleSize.md), [medianTypes](../metrics/medianTypes.md), [C4](C4.md).
