# E3 — Ceremonial interface

| Field | Value |
|---|---|
| Code | `E3` |
| Class | `trigger` |
| Analyzer | `TypeSmellAnalyzer` |
| Commands | `map` and `gate` (unless `knownFindings`) |

## When it fires

Scored `kind == "interface"` with:

- **exactly one** inbound `EdgeKind.Implementation`
- **≤ 1** distinct `fromTypeId` among **other** inbound edges (calls, parameters, …)

Zero implementations in-solution does **not** fire (implementation may live outside the snapshot). Cap 20.

Fingerprint: `ForTypeEdge("E3", interfaceTypeId, implTypeId, [])`. Message: `ceremonial abstraction: {iface} <- {impl}`.

## Example

```csharp
public interface IAccountService { void Run(); }
public sealed class AccountService : IAccountService { public void Run() { } }
// only AccountService implements it; only one other type injects IAccountService → E3
```

A port implemented once but injected in many modules is **not** ceremonial (otherFrom.Count > 1).

## How to fix

If there is no second implementation and no second consumer, **delete the interface** and use the concrete type inside the same module. Keep the interface when it is a **module port** that other modules (or a future second adapter) should depend on — then give it a second production consumer or put it on `*.Contracts`.

Test assemblies are not scored, so a “for tests only” mock does **not** count as a second consumer. A single production injector still looks ceremonial.

## What not to do

- Do **not** add a second fake implementation in production to dodge E3.
- Do **not** add a unused second consumer class.
- Do **not** treat every E3 as evil: a module-internal interface with one consumer can still be the right seam — accept the trigger or keep the interface at the **contract** boundary where multiple modules should consume it.
