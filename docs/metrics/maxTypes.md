# maxTypes

<!-- report-chip: max types -->

| Поле | Значение |
|---|---|
| Ключ в `metrics.json` | `maxTypes` (целое число, 0 и больше) |
| Чип на вкладке Metrics | **max types** (целое число; тысячи отделяются запятой: `1,204`) |
| Где считается | `StaticMetricsCalculator.Max(typeCounts)` по словарю `moduleSizes` |
| Порог / связанные правила | порога в `baseline.json` нет; правило [C1](../findings/C1.md) проверяет размер каждого модуля отдельно, и его срабатывание выражается через `maxTypes` и [medianTypes](medianTypes.md) |

## Термины

**Размер модуля в типах** (`moduleSize[m].types`, см. [moduleSize](moduleSize.md)) — число типов во всех сборках модуля с ролями, отличными от `host` и `test`. Считается любое именованное объявление: класс, интерфейс, структура, перечисление, делегат, запись, каждый вложенный тип отдельно, независимо от доступности. Контрактная сборка входит в размер своего модуля наравне с реализацией.

## Что измеряет

Метрика отвечает на вопрос: **сколько типов содержит самый крупный учитываемый модуль**.

```text
typeCounts = [ moduleSize[m].types  для каждого m из graph.Modules ]
maxTypes   = typeCounts.Length == 0 ? 0 : max(typeCounts)
```

Пример из юнит-теста `C1_median_and_max_of_per_module_sizes`: модуль `Small` с одним типом и модуль `Big` с тремя дают `maxTypes = 3` при медиане `2.0`.

Связь с правилом C1 точная. Правило срабатывает для модуля `m`, когда `types(m) >= 20` и `types(m) >= 3 × medianTypes`. Если этому условию удовлетворяет хотя бы один модуль, ему удовлетворяет и самый крупный, и наоборот. Поэтому **находка C1 присутствует в снимке тогда и только тогда, когда `maxTypes >= 20` и `maxTypes >= 3 × medianTypes`**; сколько именно модулей её получили, по двум чипам не видно — это показывает вкладка Findings.

## Как читать

- **Какой модуль.** Чип не называет модуль; найдите строку с этим числом в колонке Types таблицы Modules на той же вкладке или ключ с таким `types` в объекте `moduleSize` файла `metrics.json`. Строки таблицы упорядочены по имени модуля, а не по размеру.
- **Это счёт типов, а не строк.** Модуль из сорока однострочных записей-DTO окажется «крупнее» модуля из десяти классов по тысяче строк. Для объёма в строках есть пара [medianLoc](medianLoc.md) / [maxLoc](maxLoc.md); расхождение двух пар само по себе информативно.
- **Порога нет.** Команда `gate` никогда не сравнивает `maxTypes` ни с чем, `arch-lens baseline` его не сохраняет. Динамику видно только при сравнении `metrics.json` двух снимков; правило [C4](../findings/C4.md) (только с `gate --against old-graph.json`) автоматизирует одно такое сравнение — рост числа типов по модулям.
- **Читать вместе с медианой.** Само число ничего не значит без масштаба: `maxTypes = 45` при медиане `40` — ровная система, при медиане `6` — один модуль вобрал в себя всё. Отношение `maxTypes / medianTypes` — самый короткий индикатор перекоса.
- **Где искать.** Чип `max types` на вкладке Metrics; ключ `maxTypes` в `metrics.json`; строка модуля в таблице Modules; при срабатывании C1 — строка `C1` с сообщением `size outlier: {module}` на вкладке Findings и в `findings.json`.

## Что считать плохим

- **`maxTypes >= 20` и `maxTypes >= 3 × medianTypes`** — в снимке есть находка [C1](../findings/C1.md) класса `trigger`; при `gate` она даст вердикт `triggers`, если её отпечаток не занесён в `knownFindings`.
- **`maxTypes` растёт от снимка к снимку при неподвижной медиане** — вся новая работа ложится в один модуль. С `--against` это поймает [C4](../findings/C4.md): модуль, взявший 70 % и более положительного прироста типов при приросте от 5, получает находку.
- **Большой `maxTypes` при большой медиане**, когда C1 молчит, — повод посмотреть на состав модуля: [C2](../findings/C2.md) отмечает непрозрачное тело (типов тела вчетверо больше контрактных при 20 и более типах тела), [E1](../findings/E1.md) — типы-«боги» по числу связей.
- **Не всякий крупный модуль — проблема.** Модуль `shared` с богатой системой типов-значений или модуль с большим контрактом из десятков DTO могут возглавлять таблицу законно. Плохим является модуль, крупный за счёт реализации без соразмерного контракта, и модуль, растущий быстрее остальных.
