# cohesion

|---|---|
| Ключ в `metrics.json` | `cohesion` — объект модуль → `{ h, islands }`; в него попадают только модули с четырьмя и более учитываемыми типами |

## Термины

**Внутреннее ребро модуля** — [ребро между типами](../glossary.md#edge-kinds), у которого и источник, и цель принадлежат одному [учитываемому модулю](../glossary.md#scored). Рёбра в другие модули, а также рёбра из сборок `host` и `test` внутренними не считаются.

**Реляционная связность** `h` — среднее число внутренних упоминаний на тип: насколько типы модуля действительно работают друг с другом.

**Остров типов** — компонента связности графа типов модуля, построенного по внутренним рёбрам **без учёта направления**: если `A` ссылается на `B`, они на одном острове, кто бы из них ни был источником. Тип без единого внутреннего ребра — остров из одного типа. Число островов показывает, из скольких независимых кусков состоит модуль.

## Что измеряет

```text
N = число учитываемых типов модуля (все сборки модуля, кроме host и test)
R = Σ weight по внутренним рёбрам модуля, всех видов, в обе стороны
h = (R + 1) / N                — только при N >= 4; модули с 1–3 типами в словарь не попадают
islands = число компонент связности неориентированного графа типов модуля
```

Почему в числителе `R + 1`. Формула унаследована от реляционной связности NDepend (`H = (R + 1) / N`), где единица добавлена, чтобы у модуля без внутренних связей связность не обращалась в ноль. Следствие: `h` никогда не равно нулю, и у четырёх никак не связанных типов `h = 1 / 4 = 0.25`, а не `0` (тест `Four_unrelated_types_are_below_H_floor`, там же `islands = 4`). Второе отличие от классического определения: `R` — сумма **весов**, то есть упоминаний, а не число связанных пар. Один класс, вызывающий соседа двадцать раз, даёт `R = 20` и `h = 21 / 4 = 5.25` (тест `Four_types_with_R_20_are_above_H_ceiling`), хотя связаны всего два типа из четырёх.

Веса разных видов рёбер складываются: `call: 7` и `parameter: 5` между одной парой дают `R = 12`, `h = 13 / 4 = 3.25` и три острова — пару и два одиночных типа (тест `Intra_module_edge_weights_sum_across_kinds`). Границы включительны: `R = 5` даёт `h = 1.5`, `R = 15` даёт `h = 4`, и ни то, ни другое не является D1 (тест `H_at_floor_and_ceiling_are_not_D1`).

Острова: шесть типов, соединённых цепочками `T0 – T1 – T2` и `T3 – T4 – T5`, дают `islands = 2` и находку `disconnected islands: M` (тест `Second_island_of_three_types_is_D2`). Цепочка из пяти типов плюс одиночный тип тоже даёт `islands = 2`, но второй остров размером `1` меньше трёх, и D2 молчит (тест `Five_plus_isolated_type_is_not_D2`).

## Как читать

- Колонка `h` выводится как целое число, если значение целое (`4`), иначе с двумя знаками (`0.25`, `5.25`); `islands` — целое число. В `metrics.json` это `cohesion.<модуль>.h` и `cohesion.<модуль>.islands`.
- Здоровый диапазон `h` — от `1.5` до `4` включительно. Ниже — «мешок типов»: типы лежат в одной сборке, но почти не обращаются друг к другу. Выше — плотный клубок: несколько типов очень часто дёргают друг друга.
- `islands = 1` означает единый модуль. Большее число само по себе не находка: одиночные вспомогательные типы дают лишние острова, а D2 реагирует только на второй остров из трёх и более типов.
- Отсутствие модуля в таблице означает, что у него меньше четырёх типов, и D1/D2 для него невозможны. Отсутствие всего раздела Cohesion означает, что таких модулей нет вовсе.
- Внешние связи на `h` не влияют: четыре типа, каждый из которых по двадцать раз обращается к другому модулю, дают `h = 0.25` (тест `Edges_to_other_modules_do_not_count_in_R`). Низкая связность при высоком fan-out — подсказка для [P1](../findings/P1.md).
- Роли внутри модуля не различаются: рёбра из реализации в собственный контракт — внутренние и повышают `h`.

## Что считать плохим

- **`h < 1.5`** — типы собраны в модуль по имени папки, а не по совместной работе; модуль удобнее разобрать по островам или влить в соседей ([D1](../findings/D1.md), сообщение `sparse cohesion`).
- **`h > 4`** — либо тип-«бог», который упоминает всех остальных (проверьте [E1](../findings/E1.md)), либо два типа, переплетённые сотнями вызовов (`dense cohesion`).
- **Второй остров из трёх и более типов** — под одним именем живут две фичи; их стоит разделить на два модуля ([D2](../findings/D2.md)).
- **Много одиночных островов при нормальном `h`** — D2 не сработает, но модуль тянет за собой типы, которыми не пользуется: кандидаты в [E2](../findings/E2.md).
