# propagationCost

<!-- report-chip: propagation -->

| Поле | Значение |
|---|---|
| Ключ в `metrics.json` | `propagationCost` (число от 0 до 1) |
| Чип на вкладке Metrics | **propagation** (то же число с тремя знаками после точки, формат `0.000`, без знака процента) |
| Где считается | `StaticMetricsCalculator.Propagation`: обход в ширину по [графу модулей](../glossary.md#module-graph) |
| Порог | `baseline.ratchets.propagationCost`; правило [B4](../findings/B4.md), класс `ratchet` |

## Термины

**Достижимость.** Модуль B достижим из модуля A, если по стрелкам графа модулей можно пройти путь `A → … → B`, двигаясь только в направлении зависимостей. Путь нулевой длины тоже считается: каждый модуль достижим из самого себя. Множество достижимых из A модулей — всё, от чего A зависит напрямую или через посредников; вес рёбер значения не имеет, ребро весом 1 и ребро весом 900 открывают одинаковый путь. В коде это `ReachableCount`: обход в ширину по словарю `successors`, где для каждого модуля записаны модули, в которые у него есть хотя бы одно ребро.

**Стоимость распространения изменений** (propagation cost) — доля упорядоченных пар модулей `(a, b)`, в которых `b` достижим из `a`, среди всех `N × N` пар. Сумму можно читать в обе стороны: «сколько модулей затронет изменение в `b`» (все, из которых `b` достижим) даёт то же число, что «от скольких модулей зависит `a`».

## Что измеряет

```text
N               = число учитываемых модулей, у которых есть хотя бы один тип (graph.Modules.Count)
reach(m)        = число модулей, достижимых из m по рёбрам графа модулей, включая сам m
propagationCost = N == 0 ? 0 : Σ reach(m) по всем m / (N × N)
```

Пример из юнит-теста `B4_propagation_is_reachable_pairs_over_n_squared`: два модуля и одно ребро `A → B`. Из `A` достижимы `{A, B}`, из `B` — только `{B}`; сумма `2 + 1 = 3`, знаменатель `2 × 2 = 4`, результат `0.75`.

Два крайних случая задают шкалу:

- **Рёбер нет.** Каждый модуль достигает только себя, сумма равна `N`, значение равно `N / N² = 1 / N`: для двух изолированных модулей `0.5`, для десяти `0.1`, для решения из одного модуля `1`.
- **Полная взаимная достижимость.** Все модули лежат в одной циклической компоненте, каждый достигает все `N`, сумма равна `N²`, значение равно `1`. Цикл `A → B → C → A` даёт `9 / 9 = 1.0`; цепочка `A → B → C` без замыкания — `(3 + 2 + 1) / 9 ≈ 0.667`.

## Как читать

- **Нижняя граница зависит от `N`.** Значение `0.25` для четырёх модулей означает полное отсутствие связей, а для двадцати — заметную связность. Сравнивать метрику между разными системами бессмысленно; сравнение с собственным прошлым значением и есть смысл порога в `baseline.json`.
- **Метрика реагирует на число модулей, а не только на рёбра.** Добавление изолированного модуля `C` к паре `A → B` снижает значение с `0.75` до `(2 + 1 + 1) / 9 ≈ 0.444`; удаление такого модуля (например, мёртвого модуля из [P3](../findings/P3.md)) или слияние двух модулей поднимает его обратно без единой новой зависимости.
- **Роли и веса не учитываются.** Ребро в контрактную сборку и ребро в обход контракта открывают одинаковый путь; рёбра из сборок `host` и `test` в граф модулей не входят вовсе. Метрика измеряет форму графа, а не соблюдение границ.
- **Циклы дают максимум.** Внутри циклической компоненты каждый модуль достигает каждый, поэтому новый цикл ([B1](../findings/B1.md), метрика [cycles](cycles.md)) резко поднимает значение. Длинная ациклическая цепочка ([B6](../findings/B6.md), метрика [maxModulePath](maxModulePath.md)) поднимает его медленнее.
- **Чип округляет, гейт — нет.** Чип показывает три знака, а сравнение с порогом выполняется над точным числом из `metrics.json`: два значения, одинаковые на чипе, могут различаться в шестом знаке и дать находку B4. Сравнивайте `metrics.json` с `baseline.json`, а не чипы двух отчётов.
- **Где искать.** Чип `propagation` на вкладке Metrics; ключ `propagationCost` в `metrics.json`; порог `ratchets.propagationCost` в `baseline.json`; при срабатывании — запись `"rule": "B4"` в `gate-report.json` с сообщением `propagationCost {текущее} > baseline {порог}`. На вкладке Matrix аналога нет: матрица строится по компонентам из `rules`, а не по модулям (см. [отличие DSM от графа модулей](../glossary.md#dsm-vs-modules)).

## Что считать плохим

- **Любое строгое увеличение относительно `baseline.ratchets.propagationCost`** — находка [B4](../findings/B4.md) класса `ratchet`, вердикт `block`. Сравнение выполняется оператором `>` без допуска; равенство и уменьшение вердикт не меняют. Отсутствующий ключ читается как `0`, а при `N > 0` значение всегда положительно, поэтому такой baseline блокирует всегда.
- **Значение, близкое к `1`, при `N` больше двух-трёх** — почти все модули взаимно достижимы: есть крупная циклическая компонента либо узел, который зависит от всех и от которого зависят все. Проверьте раздел Cycles, метрики [coreSize](coreSize.md) и [coreShare](coreShare.md).
- **Рост от одного нового ребра** для этой метрики нормален: ребро из конца цепочки в её начало замыкает цикл и переводит целую группу модулей в состояние полной достижимости. Именно такие рёбра гейт и должен останавливать.
- **Снижение за счёт дробления модуля на изолированные части** — не улучшение, а эффект `1 / N`: если части по-прежнему нужны друг другу через `shared` или контракты, связность не изменилась.

**Когда допустимо принять.** Рост из-за удаления мёртвого модуля, слияния модулей или осознанно добавленной зависимости фиксируется командой `arch-lens baseline`; новый `baseline.json` коммитится вместе с изменением, причина роста описывается в коммите.
