| Поле | Значение |
|---|---|
| Ключ в `metrics.json` | `medianLoc` (число; при чётном числе модулей возможны половинные значения) |
| Чип на вкладке Metrics | **median loc** (целое значение с разделителем тысяч, например `1,250`; половинное — с дробной частью и без разделителя, например `1250.5`) |

| Порог / связанные правила | порога в `baseline.json` нет; ни одно правило эту метрику не читает. Правило [C3](../findings/C3.md) работает с разбивкой строк по ролям ([layerLoc](layerLoc.md)), а не с этой медианой |

## Термины

**LOC типа** (`Loc`, [словарь](../glossary.md#loc)) в этом инструменте — число строк исходного текста, занятых объявлением типа: от строки, где начинается объявление, до строки, где оно заканчивается, включительно (`CountLoc` в `RoslynGraphExtractor`). Это физические строки, а не операторы: пустые строки и комментарии внутри объявления, атрибуты самого типа и его членов входят в счёт, а директивы `using`, объявление пространства имён и комментарии над типом (включая XML-документацию) — нет. У `partial`-типа складываются все части. Части, лежащие в файлах с суффиксами `.g.cs`, `.g.i.cs` и `.generated.cs`, не считаются; файлы с другими именами (`*.Designer.cs`, вручную скопированный сгенерированный код) считаются как обычные. Строки вложенного типа входят и в его собственный `Loc`, и в `Loc` внешнего типа, поэтому в сумме по модулю они учтены дважды.

**LOC модуля** (`moduleSize[m].loc`) — сумма `Loc` всех типов модуля в сборках с ролями, отличными от `host` и `test`, включая контрактную сборку.

**Медиана** ([словарь](../glossary.md#median)) — центральный элемент отсортированного набора или среднее двух центральных при чётном числе элементов; один огромный модуль её почти не сдвигает.

## Что измеряет

Метрика отвечает на вопрос: **сколько строк занимает «типичный» учитываемый модуль**.

```text
locCounts = [ moduleSize[m].loc  для каждого m из graph.Modules ], отсортированные по возрастанию
mid       = locCounts.Length / 2
medianLoc = locCounts.Length == 0 ? 0
          : locCounts.Length нечётная ? locCounts[mid]
          : (locCounts[mid - 1] + locCounts[mid]) / 2.0
```

Пример из юнит-теста `C1_median_and_max_of_per_module_sizes`: модуль `Small` с одним типом на одну строку и модуль `Big` с тремя типами по одной строке дают набор `[1, 3]` и медиану `2.0`. Для четырёх модулей объёмом `[120, 300, 480, 2000]` строк медиана равна `(300 + 480) / 2 = 390`; модуль на 2000 строк — выброс, и на медиану он не влияет.

## Как читать

- **Формат чипа зависит от значения.** Целая медиана выводится как целое с разделителем тысяч (`1,250`), половинная — как дробное число без разделителя (`1250.5`). В `metrics.json` оба варианта — обычные числа.
- **Читать парой с [medianTypes](medianTypes.md).** Отношение `medianLoc / medianTypes` — средний размер типа в типичном модуле. Если медиана строк растёт, а медиана типов стоит, типы становятся толще; если наоборот — модули наполняются мелкими типами (DTO, перечисления, записи).
- **Читать парой с [maxLoc](maxLoc.md).** Разрыв между медианой и максимумом показывает, насколько один модуль тяжелее остальных по объёму кода; в типах тот же разрыв показывают [medianTypes](medianTypes.md) и [maxTypes](maxTypes.md).
- **Строки — грубая мера.** Стиль форматирования, длинные комментарии внутри типов и двойной учёт вложенных типов сдвигают число без изменения архитектуры. Метрика годится для сравнения модулей одной кодовой базы между собой и во времени, а не для сравнения с другими проектами.
- **Где искать.** Чип `median loc` на вкладке Metrics; ключ `medianLoc` в `metrics.json`; объём каждого модуля — колонка LOC таблицы Modules и поле `loc` в объекте `moduleSize`; разбивка объёма модуля по ролям сборок — таблица Layer LOC и ключ `layerLoc`.

## Что считать плохим

- **Ни одно правило по этой метрике не срабатывает**, и порога у неё нет: `gate` её не сравнивает, `arch-lens baseline` не сохраняет. Всё, что ниже, — ориентиры для чтения, а не условия находок.
- **Медиана строк растёт быстрее медианы типов** — код накапливается внутри существующих типов. Правила о размере отдельного типа в строках у инструмента нет; [E1](../findings/E1.md) ищет типы-«боги» по числу связей, а не по строкам, поэтому толстые, но малосвязанные типы придётся искать вручную по таблице Modules.
- **Резкий скачок медианы после одного коммита** чаще всего означает, что в решение попал сгенерированный код в файлах без суффикса `.g.cs` или `.generated.cs`: экстрактор считает такие файлы обычным исходным текстом. Переименование файлов или вынос генерации в отдельную сборку `host` уберёт шум.
- **Модуль, у которого строки UI превышают строки реализации**, получит находку [C3](../findings/C3.md) — но по таблице Layer LOC, а не по медиане.
