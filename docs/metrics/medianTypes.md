# medianTypes

<!-- report-chip: median types -->

| Поле | Значение |
|---|---|
| Ключ в `metrics.json` | `medianTypes` (число; при чётном числе модулей возможны половинные значения, например `5.5`) |
| Чип на вкладке Metrics | **median types** (целое число либо число с дробной частью до двух знаков: `5` или `5.5`) |
| Где считается | `StaticMetricsCalculator.Median(typeCounts)` по словарю `moduleSizes` |
| Порог / связанные правила | порога в `baseline.json` нет; правило [C1](../findings/C1.md) использует медиану как масштаб: `types >= 20 && types >= 3 * medianTypes` |

## Термины

**Медиана** ([словарь](../glossary.md#median)) — значение, стоящее в середине отсортированного набора. При нечётном числе элементов это центральный элемент; при чётном — среднее арифметическое двух центральных, откуда и берутся половинные значения. В отличие от среднего арифметического медиану не сдвигает один огромный элемент: набор `[4, 7, 9, 30, 31]` имеет медиану `9`, хотя среднее равно `16.2`. Именно это свойство делает медиану пригодным масштабом для поиска выбросов: модуль-«гигант», который C1 должна поймать, сам почти не влияет на порог, с которым его сравнивают.

**Размер модуля в типах** — число типов во всех сборках модуля с ролями, отличными от `host` и `test`, включая контрактную сборку; см. [moduleSize](moduleSize.md).

## Что измеряет

Метрика отвечает на вопрос: **сколько типов содержит «типичный» учитываемый модуль**.

```text
typeCounts  = [ moduleSize[m].types  для каждого m из graph.Modules ], отсортированные по возрастанию
mid         = typeCounts.Length / 2
medianTypes = typeCounts.Length == 0 ? 0
            : typeCounts.Length нечётная ? typeCounts[mid]
            : (typeCounts[mid - 1] + typeCounts[mid]) / 2.0
```

В набор входит по одному числу на каждый учитываемый модуль, у которого есть хотя бы один тип, поэтому при непустом графе медиана не меньше `1`.

Пример из юнит-теста `C1_median_and_max_of_per_module_sizes`: модуль `Small` с одним типом и модуль `Big` с тремя типами дают набор `[1, 3]`, медиану `(1 + 3) / 2 = 2.0` и [maxTypes](maxTypes.md) `3`. Для четырёх модулей с размерами `[4, 7, 9, 30]` медиана равна `(7 + 9) / 2 = 8`; модуль на 30 типов остаётся выбросом и не подтягивает порог к себе.

## Как читать

- **Чип показывает то же число, что и JSON.** Целое значение выводится без дробной части (`8`), половинное — с ней (`8.5`); в `metrics.json` оба лежат как числа.
- **Фактический порог C1 равен `max(20, 3 × medianTypes)`.** Правило требует одновременно `types >= 20` и `types >= 3 × medianTypes`, поэтому при медиане `6.5` и меньше решает нижняя граница в 20 типов (`3 × 6.5 = 19.5`), а при медиане `7` и больше — тройной масштаб. Медиана `12` означает, что находку получит только модуль от 36 типов.
- **При малом числе модулей медиана скачет.** Для двух модулей это просто среднее их размеров; добавление третьего модуля переводит медиану на конкретный модуль. Оценивать «типичный размер» по медиане имеет смысл от четырёх-пяти модулей.
- **Медиана не растёт вместе с системой.** Если новые типы ложатся в существующие крупные модули, медиана стоит на месте, а разрыв между ней и [maxTypes](maxTypes.md) увеличивается — это и есть сигнал, который ловит C1, а с `--against` — [C4](../findings/C4.md).
- **Где искать.** Чип `median types` на вкладке Metrics; ключ `medianTypes` в `metrics.json`; исходные размеры каждого модуля — колонка Types таблицы Modules и объект `moduleSize` в JSON.

## Что считать плохим

- **Сама по себе медиана не бывает «плохой»**: это масштаб, а не показатель качества. Плохим или хорошим является соотношение с ней конкретных модулей.
- **Медиана в 1–3 типа при десятке модулей** означает, что систему разрезали слишком мелко: модули-заготовки с одним интерфейсом занижают масштаб, и C1 срабатывает на любой модуль от 20 типов, даже если он нормального размера. Лечится не «раздуванием» мелких модулей, а слиянием заготовок в осмысленные модули.
- **Очень большая медиана (десятки типов)** делает C1 практически неработоспособной: тройной масштаб уходит за сотню типов. Тогда за размером следят через [maxTypes](maxTypes.md), [C2](../findings/C2.md) (непрозрачное тело: типов тела в четыре и более раз больше, чем контрактных, при 20 и более типах тела) и [C4](../findings/C4.md).
- **Медиана падает без удаления кода** — значит, появились новые маленькие модули. Проверьте, не заготовки ли это без потребителей ([P3](../findings/P3.md)) и не пропала ли у них связь с тестами ([F2](../findings/F2.md)).
